# Агент печати этикеток (ПК склада, TSC MB341)

Маленькая программа на PowerShell для ПК склада. Каждые 3 секунды спрашивает ERP, нет ли этикеток на печать, и отправляет их на принтер TSC через очередь Windows. Python не нужен, ничего не нужно открывать: агент работает скрыто и стартует сам при входе в Windows.

## Что нужно заранее
- Принтер TSC MB341 подключён по USB, драйвер TSC установлен, в «Принтеры и сканеры» он виден (очередь печати).
- Токен ERP со scope `labels:print`. Его создаёт администратор в ERP. Токен показывается один раз, скопируйте его.

## Сканер с любого ПК (с 28.10.2026)
Агент ставится на любой ПК с Windows, где нужен сканер (права администратора Windows не нужны). Он сам называет себя серверу (MachineGuid и имя ПК), раз в ~2 минуты сообщает версию, найденные WIA-сканеры (первый найденный работает, подключённый позже подхватится) и адрес в сети; принтер этикеток необязателен. Кнопка «Сканировать» в ERP уходит на ПК, за которым сидит человек (сервер сопоставляет адрес браузера и агента); если таких несколько, показывается выбор, если нет ни одного, окно с инструкцией.

Установка на новом ПК: администратор ERP открывает окно «Установка сканера» (оно появляется само при нажатии «Сканировать», когда агента нет) и копирует команду с одноразовым токеном (живёт час). Команду выполнить в PowerShell на том ПК. Токен меняется на токен API агента (`labels:print` + `scan:upload`, 365 дней), файл агента скачивается с сервера и сверяется по SHA-256. Дальше агент обновляется сам: сервер знает версию из `$script:AgentVersion` в `agent.ps1` (поднимайте число при каждом изменении), агент скачивает файл, проверяет хэш и разбор, подменяет себя (старый остаётся как `agent.ps1.bak`) и перезапускает задачу.

Старый агент (версия 1, без номера ПК) работает как раньше: берёт задания «для любого агента». Чтобы перевести ПК склада на новую схему, один раз выполните команду из ERP на этом ПК.

## Установка из папки (одна команда)
1. Скопируйте папку `tools\print-agent` на ПК склада.
2. Откройте PowerShell в этой папке (в Проводнике: адресная строка, набрать `powershell`, Enter) и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Token "ТОКЕН_ИЗ_ERP"
```

Сервер по умолчанию `https://erp-server.tail811f20.ts.net`. Другой сервер: `-Server "https://..."`.
Принтер выбирается сам: первая очередь, в названии которой есть «TSC». Если такой нет, установка остановится и покажет список очередей; тогда укажите нужную: `-Printer "имя очереди"`.

Установщик копирует агент в `C:\ProgramData\FraxisPrintAgent`, сохраняет настройки (токен зашифрован средствами Windows и читается только вашим пользователем на этом ПК), создаёт задачу «Fraxis — печать этикеток» (запуск при входе, перезапуск при сбое) и сразу запускает её.

## Как узнать имя очереди принтера
```powershell
Get-Printer | Select-Object Name, DriverName, PortName
```
Или: Параметры, Устройства, Принтеры и сканеры, имя принтера в списке. Это имя и нужно в `-Printer`.

## Как проверить, что работает
1. Журнал: `Get-Content C:\ProgramData\FraxisPrintAgent\agent.log -Tail 20`. Должна быть строка «Агент запущен», без повторяющихся ошибок «Сеть/сервер».
2. Задача: `Get-ScheduledTask -TaskName "Fraxis — печать этикеток"` (состояние Running).
3. В ERP отправьте этикетку на печать. Она выйдет на принтере, в журнале появится «Напечатано: задание ...».
4. Проверка без бумаги: остановите задачу и запустите один опрос в режиме «понарошку» (задание из очереди ERP будет взято и помечено как ошибка «dry run», этикетка не напечатается):
```powershell
Stop-ScheduledTask -TaskName "Fraxis — печать этикеток"
powershell -ExecutionPolicy Bypass -File C:\ProgramData\FraxisPrintAgent\agent.ps1 -DryRun -Once
Start-ScheduledTask -TaskName "Fraxis — печать этикеток"
```

## Если что-то не так
- Нет связи с сервером: агент пишет в журнал, ждёт 3, 6, 12, 24, 30 секунд и пробует снова; ничего перезапускать не нужно.
- Принтер выключен или очередь названа иначе: задание вернётся в ERP с ошибкой (код Windows в тексте), этикетку можно отправить повторно.
- Сменили принтер или токен: запустите `install.ps1` ещё раз с новыми параметрами.
- Журнал `agent.log` сам переименовывается в `agent.log.1` при размере около 1 МБ. Токен в журнал не пишется.

## Удаление
```powershell
powershell -ExecutionPolicy Bypass -File .\uninstall.ps1
```
(то же самое: `install.ps1 -Uninstall`). Удаляет задачу и папку `C:\ProgramData\FraxisPrintAgent`. Токен в ERP после этого лучше отозвать.

## Сканер УПД (Pantum BM2300W)

Кнопка «Сканировать» в окне «Поставка» отправляет задание на ПК склада; агент сканирует лист со стекла и загружает файл в ERP, дальше УПД разбирается как обычный файл. Сканер Pantum BM2300W умеет Mopria Scan (eSCL/AirScan), поэтому драйвер сканера на ПК не нужен: агент говорит со сканером по сети.

1. Узнайте IP-адрес принтера: на панели принтера (Сеть, Wi-Fi, информация о сети), в списке клиентов роутера или в приложении Pantum. Лучше закрепить за принтером постоянный адрес в роутере.
2. Токену ERP нужны scopes `labels:print` и `scan:upload`.
3. Установите (или переустановите) агент с адресом сканера:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Token "ТОКЕН_ИЗ_ERP" -Scanner "192.168.1.50"
```

4. Проверка без ERP: положите лист на стекло и выполните

```powershell
Stop-ScheduledTask -TaskName "Fraxis — печать этикеток"
powershell -ExecutionPolicy Bypass -File C:\ProgramData\FraxisPrintAgent\agent.ps1 -TestScan
Start-ScheduledTask -TaskName "Fraxis — печать этикеток"
```

Агент выведет возможности сканера (модель, форматы, стекло), отсканирует лист и сохранит `C:\ProgramData\FraxisPrintAgent\test-scan.pdf` (или `.jpg`). Откройте файл: лист должен быть целиком. В журнале строки «Скан: ...».

- Скан идёт с планшета (стекла), A4, серый, 300 dpi, PDF; если сканер не принимает PDF, агент повторяет в JPEG. Сначала пробуется http, потом https (сертификат сканера самоподписанный, проверка отключается только для обращения к нему).
- Если `-Scanner` не задан, агент ищет USB-сканер через Windows (WIA, первое устройство-сканер) и сканирует в JPEG. Нужен установленный драйвер сканера.
- Журнал: «Скан: задание ...», «Скан отправлен ...», «Скан: ошибка ...». Текст ошибки уходит и в ERP, оператор видит его в окне «Поставка». Ошибка скана печать этикеток не останавливает.
- Не отвечает сканер: проверьте, что принтер включён и в той же сети, что и ПК; `Test-NetConnection 192.168.1.50 -Port 80`. Адрес сменился: переустановите с новым `-Scanner`.

## ВАЦ (Planar S2VNA и Arinst)

Агент версии **2.5.0** поддерживает снятие трассы с Planar S50180 через установленную на этом ПК S2VNA
и получение последнего сохранённого файла Arinst VNA-DL.
SCPI-сервер включать не нужно. Heartbeat проверяет процесс S2VNA и подключённое USB-устройство Planar (VID_2226, статус OK), без обращения к COM; при задании агент может запустить S2VNA.
IDN последнего успешно прочитанного прибора сохраняется в `vna-idn.txt` рядом с `config.json` и переживает перезапуск агента. СИ выбирает оператор в ERP; приложение задаётся в карточке СИ полем **Программа ВАЦ**.

1. Подключите ВАЦ, откройте S2VNA и дождитесь готовности прибора.
2. Откалибруйте измерительный тракт, задайте полосу и выберите нужную трассу **S11 или S22 в канале 1**.
3. В ERP: **ОТК → Замеры КСВН → задание → Загрузить замер → Снять с ВАЦ**. Выберите действующее СИ с программой **S2VNA**.
4. Дождитесь файла `vna.s1p`. Выбранное СИ переносится в замер. Проверьте настройки и предупреждения, затем нажмите **Загрузить замер**.

Агент читает текущие точки выбранной трассы; не меняет калибровку, формат, полосу, настройки и не запускает новый свип.
Не меняйте трассу или полосу во время чтения. S21/S12, неготовый прибор, неполные данные и файл больше 2 МиБ дают ошибку.

С трассой передаётся JSON `capture_settings`: число точек, старт/стоп (Гц), полоса ПЧ (Гц), усреднение и его фактор,
сглаживание и апертура (%), включение коррекции, её статус и S-параметр. Максимальный шаг частоты берётся из фактической
сетки, чтобы проверка плотности работала и при неравномерных точках. Настройки показаны в окне загрузки и хранятся
в существующем JSON `file_meta` замера. Недоступные свойства перечислены в `unavailable`; неизвестное значение не означает «выключено».
Сглаживание, отсутствие/интерполяция/экстраполяция калибровки, неполный диапазон нормы и редкая сетка для известной длины
дают предупреждения. Агент не исправляет настройки прибора.

Имена COM проверены по локальному «Руководству по эксплуатации S2VNA», часть 2 (все операции — чтение):

| Настройка | COM-свойство | Страница |
| --- | --- | --- |
| Точки | `SCPI.SENSe(1).SWEep.POINts` | 2079 |
| Старт / стоп | `SCPI.SENSe(1).FREQuency.STARt` / `.STOP` | 2015 / 2017 |
| Полоса ПЧ | `SCPI.SENSe(1).BANDwidth.RESolution` | 1703 |
| Усреднение / фактор | `SCPI.SENSe(1).AVERage.STATe` / `.COUNt` | 1696 / 1700 |
| Сглаживание / апертура | `SCPI.CALCulate(1).SELected.SMOothing.STATe` / `.APERture` | 1420 / 1423–1424 |
| Коррекция включена | `SCPI.SENSe(1).CORRection.STATe` | 1970 |
| Статус коррекции | `SCPI.CALCulate(1).SELected.CORRection.STATus` | 1123–1125 |

Статусы для S-параметров: `NONE` — коррекция не применяется, `COR` — полная, `C?` — интерполяция,
`C!` — экстраполяция (выход за диапазон калибровки). S-параметр читается существующим `CALCulate(1).PARameter(trace).DEFine`.
### Arinst VNA-DL — последний сохранённый файл

1. В **Arinst Virtual Lab** откалибруйте тракт и выполните измерение.
2. Нажмите **Сохранить**, выберите Touchstone **.s1p** и сохраните файл в «Документы», «Рабочий стол» или «Загрузки»
   (допускается вложенная папка на один уровень). Файлы **.s2p** тоже поддерживаются: ERP использует S11.
3. В ERP: **ОТК → Замеры КСВН → задание → Загрузить замер → Снять с ВАЦ** → выберите СИ с программой **Arinst VL**.
4. Проверьте имя полученного файла и выбранное СИ. Нажмите **Загрузить замер**.

Источник Arinst появляется, если на ПК установлен `%APPDATA%\ArinstVL*\ArinstVL.exe`. Запускать Arinst VL для
передачи уже сохранённого файла не требуется. Агент выбирает самый новый `.s1p`/`.s2p` за последние **15 минут**
среди всех отслеживаемых папок, передаёт исходные байты и имя, не удаляет и не перемещает файл.
Перед снятием сохраните нужную трассу последней; файл больше **2 МиБ** даёт ошибку без подмены более старым.
Агент не обращается к прибору по serial/COM: калибровку применяет Arinst Virtual Lab при измерении и сохранении.

Другие папки задаются списком `arinstFolders` в `config.json` агента (остальные поля настроек сохраните):

```json
"arinstFolders": ["C:\\Measurements", "D:\\ОТК\\Arinst"]
```

Настройка заменяет папки по умолчанию; пустой список отключает поиск. Агент читает её при каждом снятии.
Для обоих источников остаётся доступна кнопка **Выбрать файл…**.

Если ПК не найден, установите S2VNA или Arinst Virtual Lab и агент ERP по инструкции в окне. Существующий токен со scope `scan:upload`
подходит; новый токен не нужен. После публикации серверной версии работающий агент обновится сам по heartbeat
(до двух минут плюс перезапуск). Версию 2.5.0 проверьте в журнале агента и повторите один замер.

Проверки без прибора: `Invoke-Pester tools\print-agent\tests\agent-vna.Tests.ps1` (COM полностью подменён).
Транспорт ВАЦ использует общие heartbeat/claim/result сканера: heartbeat сохраняет `vna: {name, ready, reason}` для S2VNA
и добавляет `vna_sources: ["s2vna", "arinst"]` (только установленные источники); claim
передаёт `kinds: ["scan", "vna"]`, задание возвращает `kind` и `source`; результат — multipart с `.s1p`/`.s2p` в поле `file`
и необязательным JSON-полем `capture_settings` (S2VNA) либо JSON ошибки с заголовком `X-Agent-Machine-Id`.
Старый агент без `kinds` получает только сканы. ERP ищет агент с нужной программой по адресу браузера;
при нескольких совпадениях оператор выбирает ПК. Общий внешний IP может дать несколько кандидатов, поэтому однозначность обязательна.

## Контракт и тесты агента
- Контракт с сервером: `POST /api/stock/labels/agent/claim` `{printer, host}` -> `{job: {id, copies, tspl_b64} | null}`; `POST /api/stock/labels/agent/jobs/<id>/result` `{ok, error}`; заголовок `Authorization: Bearer <токен>`. Копии уже внутри TSPL (`PRINT n`), агент отправляет задание один раз.
- Скан: `POST /api/stock/scan/agent/claim` `{host}` -> `{job: {id} | null}`; `POST /api/stock/scan/agent/jobs/<id>/result` — `multipart/form-data` с полем `file` (PDF или JPEG) либо JSON `{"error": "..."}`. Тесты: `tools\print-agent\tests\agent-scan.Tests.ps1`.
- Тесты: `Invoke-Pester tools\print-agent\tests\agent.Tests.ps1` (Pester 3+, печать подменена). Ручной сквозной тест с мок-сервером: `powershell -NoProfile -ExecutionPolicy Bypass -File tools\print-agent\tests\mock-server.ps1`.
- Файлы `.ps1` хранятся в UTF-8 с BOM: Windows PowerShell 5.1 иначе портит кириллицу.
