# Исторические реквизиты отгрузки

После перехода в «Отгружена» реквизиты отправки больше не обновляются из текущей карточки проекта.
То же ограничение действует для «Закрыта» и «Отменена». Активные отправки продолжают наследовать
карточку проекта. Обычное редактирование шапки после отгрузки запрещено.

Для документально подтверждённых исправлений добавлена команда
`POST /api/shipping/shipments/{id}/history-correction`, доступная администратору и суперадминистратору.
API-токены и режим «Смотреть как сотрудник» запись не допускают.

Обязательные поля тела: `version` (текущая версия, от 1), `reason` и `source` (непустые строки,
до 2000 символов каждая). Исправляемые поля передаются непосредственно в теле:

| Поле | Максимум символов |
| --- | ---: |
| `receiver` | 512 |
| `shipping_point` | 5000 |
| `contact` | 255 |
| `phone` | 128 |
| `carrier` | 255 |
| `track_number` | 255 |

Отсутствующее поле сохраняется, пустая строка очищает значение, `null` и неизвестные поля отклоняются.
Команда работает только для «Отгружена» и «Закрыта» и возвращает `{ "shipment": ... }`.
Конфликт версии — 409, отсутствие прав — 403, неверные данные или статус — 422.

Изменённые поля исключаются из наследования. Одна успешная правка увеличивает версию на 1 и записывает
одно событие `shipping.history_corrected` в той же транзакции. Событие содержит причину, источник,
все шесть значений до и после, набор наследуемых полей, версии, автора и время. Запрос без изменений
не создаёт новую версию, аудит или уведомления. Ошибка аудита откатывает исправление целиком.

Даты, условия доставки, документы, позиции, количества, короба, ГРН и складские счётчики этой командой
не меняются. Для «Отгружена» прежняя команда документов позволяет дополнить УПД; пустой `upd_type`
сохраняет записанный тип. Изменение трека после отгрузки выполняется только исправлением истории.
При дополнении УПД отсутствующий в запросе `track_number` сохраняет исторический трек; переданная
явно пустая строка или другой трек отклоняются. Для активных отправок прежнее поведение сохраняется.

Схема БД не меняется. Исправление предотвращает дальнейшее обновление истории текущими данными;
автоматического восстановления прежних значений из сегодняшней карточки проекта нет.

Проверки: `backend/tests/shipping/test_history_correction.py`, существующие тесты модуля shipping и
проверка запрета записи в режиме просмотра сотрудника. Боевые данные и PostgreSQL этим набором не проверяются.
