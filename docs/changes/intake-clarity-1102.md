# Складская приёмка: данные и документы без лишних окон

Убираем срок проекта из заголовка склада, сохраняем даты фактической приёмки и отгрузки.
Номер ГРН читается полностью и сам запускает печать; ГРН виден также у упакованных позиций.
PL, DN и УПД — отдельные действия с наличием каждого документа. Сведения доставки — столбцами, перевозчик отдельно от трек-номера.
Используем существующую пакетную загрузку адресатов, без запроса на каждую строку. Не меняем остатки, запреты действий и историю.

Доставка и ГРН сгруппированы по отправкам: совпадающие партии в разных отправках остаются отдельными строками. Поиск и Excel берут те же ГРН, которые показаны на экране, без подмены последней партией из строки приёмки.
Явно выбранный перевозчик «Самовывоз» показывает способ «Самовывоз» и адрес «Не требуется», в том числе у старых записей без условий доставки.
Внести УПД можно в данные выбранной отправки; изменение шапки и документов проверяет актуальную версию отправки, а конфликт сервера оставляет форму с введённым номером открытой. Карточка проекта при этом не изменяется.

Проверки: два новых регрессионных теста сначала воспроизвели ошибки самовывоза и поиска ГРН; после исправления оба проходят. Обновлены проверки версии шапки/документов, запрета записи при просмотре (включая принудительную отправку формы) и конфликта 409.

После объединения с изменениями окна данных отправки: `ProductionIntakePage.test.tsx`, `ShipmentData.test.tsx`, `ShipmentDataPage.test.tsx` — 85/85; `npm run build` (TypeScript + Vite) и `git diff --check` — без ошибок. В сборке остаются предупреждения общих модулей harness о BigInt для старых браузеров и размере пакетов. Общая проверка в браузере — в работе. Эти тесты проверяют поведение, внешний вид требует общей проверки экрана.
