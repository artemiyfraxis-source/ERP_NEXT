# Заявки без отдельного «Взять в работу»

В заявках закупщика убрана промежуточная кнопка «Взять в работу» и подсказка «взять N». Новую свободную позицию можно сразу отметить и запросить КП либо отклонить через существующее окно с обязательной причиной. До создания КП просмотр, подбор поставщиков и возврат к строкам сохраняют статус «Новый» и отсутствие ответственного.

При создании КП межмодульный порт использует ту же SQLAlchemy-сессию, что запрос, его строки и поставщики. Порт блокирует выбранные строки и вызывает выделенный помощник назначения без commit: прежние правила `take_in_work`, заполнение фактического количества/единицы, поставщик из карты доменов, аудит и очередь автозаполнения сохраняются. Ошибка откатывает весь набор, включая созданного поставщика. Назначение проверяет версию строки; один живой запрос на позицию защищён существующим уникальным индексом.

Выбор доступен для своих строк на столе закупщика, включая перезапрос, и новых свободных строк. Чужие, оплаченные, закрытые, полностью покрытые со склада позиции, дозавоз и строки в живом КП исключены. При частичном покрытии в КП попадает только остаток к закупке; покрытие не изменяется. Возможность выбора для КП не даёт права редактировать факты новой строки. Общий ручной take API и другие экраны сохранены. Миграций нет.

Ограничение этого PR: сохранена прежняя семантика количества КП — `max(calculated_quantity − stock_covered, 0)`. Закупщик пока не вводит количество перед созданием КП; `actual_quantity` не меняет эту формулу, а полностью покрытая складом строка не выбирается для КП. Это отдельный шаг по устранению ручного взятия, а не реализация расширенного требования показать весь состав ЗКП и дать закупщику выбрать запрашиваемое количество. Расширение состава и количества ожидает отдельного решения пользователя.
