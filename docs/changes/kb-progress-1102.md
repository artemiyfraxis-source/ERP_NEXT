# Количества по КБ — незавершённая задача TASKS

Накопительные отметки «Начато / Готово / На ОТК / ОТК прошло» по КБ. Позднее количество поднимает ранние с уведомлением; отрицательное и превышение тиража не допускаются. Порядок этапов не блокирует работу во время тестирования.
Это предпосылка отдельного разрешения упаковки по КБ и количеству. Реальные складские движения не подменяются ручными отметками.

Во вкладке «Состав» у каждой КБ доступно действие «Количества» при праве редактирования проектов. Окно получает текущие значения отдельно для выбранной КБ; в строке показаны значения из карточки проекта. Неизвестные количества остаются «—», известный ноль показывается как 0. Просмотр не даёт права сохранения.

Сохранение отправляет только изменённые поля, номер последней записи и текущий тираж. При конфликте окно показывает ошибку, загружает свежие количества и позволяет повторить ввод. Если тираж исчез, дальнейшее сохранение недоступно. После успешной записи карточка проекта обновляется, чтобы показать фактический этап и количества.

Контракты: `GET/POST /api/techcards/kitsets/{project}/progress/{kb}` и `GET/POST /api/production/plan/kb-progress`. Снимки количеств доступны в событиях плана и по КБ; текущий тираж может быть неизвестен (`null`).

Проверено на frontend: выбор КБ2 без запроса КБ1, состав тела записи, обновление карточки, повтор после конфликта со свежим тиражом и номером записи, неизвестные значения, права просмотра, оба API-контракта и исчезновение тиража во время сохранения. Исправлен начальный фокус окна и возврат к кнопке после закрытия; 99 целевых тестов и повторный прогон 70 тестов, TypeScript и сборка прошли. Независимый review UI завершён без замечаний.

Текущий тираж читается внутри транзакции записи количеств. PostgreSQL использует общую блокировку нормализованного проекта для источников набора и выданной ТК; SQLite начинает `BEGIN IMMEDIATE` до первого чтения. Регрессии воспроизводят изменение/исчезновение тиража между чтением и записью; целевые 117 тестов прошли. Реальная конкурентность PostgreSQL этим результатом ещё не подтверждена.

История не ограничивает актуальность количеств: частичная запись читает последний снимок выбранной КБ адресным запросом; карточка, список и план пакетно добавляют последние снимки всех КБ к ограниченному журналу. Регрессия на 10 003 событиях проверяет обе КБ, точные количества и этапы; 106 целевых тестов прошли. Независимый повторный review блокировок и проекций — без замечаний.

Миграция `0166_kb_progress` после `0165_split_lug_cable_tabs`: пять nullable-полей, старые строки остаются неизвестными, неизменяемость журнала сохраняется. Независимый schema-review, SQL-компиляция PostgreSQL, три миграционных и 14 persistence-тестов прошли. [Репетиция на изолированной копии](kb-progress-1102-rehearsal.md) завершена успешно; подробные доказательства находятся в закрытых артефактах владельца. Старые миграционные fixtures и сидер адаптированы без изменения приложения/миграции и без ослабления исторических assertions: 76 прошли, 2 пропущены; независимый review — APPROVE. Полный интеграционный gate: архитектура 18, backend 6684 прошли / 51 пропущен, frontend 4640 в 432 файлах, обе сборки — PASS. Объединённый визуальный smoke просмотрен; синтетические данные не подтверждают реальные бизнес-операции.
