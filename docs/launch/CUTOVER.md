# Переход с SUPPLYMAP на ERP: запуск 01.10–05.10.2026

Блоки на запуск (владелец, 29.09): проекты, склад, запросы на комплектацию, выдача со списанием, отгрузка.
Живые данные в Google — только склад ЦАР / ЖУК / СПИСАНИЕ; Запросы, Закупка, ВЫДАЧА, ОТГРУЗКА и прочее —
тестовые (SUPPLYMAP CLAUDE.md, правило владельца 14.09), их не переносим. Проекты переносятся целиком.

## Чт 01.10 — сервер
1. Сервер создан (deploy/README.md), `push.ps1 -Server <IP>` — сайт открывается по HTTPS.
2. `load-real-data.sh base` — администратор, сотрудники с PIN, справочники, библиотека техкарт, проекты.
3. Владелец входит, проверяет проекты и план цеха; PIN сотрудников — файл `staff-pins.txt` у владельца.
SUPPLYMAP в эти дни работает как обычно.

## Пт 02.10 – вс 04.10 — склад
1. Сверка без записи: `load-real-data.sh stock` — должно быть «всё сошлось». Перед записью пересчитать на полке
   партию OLD.26.0000095 (по журналу списано 2231, в графе СПИСАНО 2387).
2. Заморозка: последний день движений склада в Google. После него на листах ЦАР / ЖУК / СПИСАНИЕ никто не
   правит (защитить листы или предупредить кладовщиков). Агенты эти листы не трогают.
3. Сразу после заморозки: `load-real-data.sh stock` (сверка) → `stock --yes` (запись, один раз) →
   `load-real-data.sh projects` (свежие проекты). Копия базы: `erp.sh backup-now`.
4. Контроль: в ERP «Склад» те же остатки по ГРН, что на листе ЦАР в момент заморозки.

## Пн 05.10 — работа в ERP
- Кладовщики, мастера, ОТК, отгрузка работают только в ERP: запрос на комплектацию → выдача (со списанием
  партий) → производство → отгрузка. Приёмка новых поставок — в ERP.
- В SUPPLYMAP склад только для чтения. Новые движения в Google в ERP сами не попадут.
- Ежедневно: копия базы в 03:00 уходит в `/opt/erp/backups` + снимок диска Timeweb.

## 05.10–09.10 — вторая волна: заявки, лист закупки, приёмка
Владелец, 29.09: в течение недели после 05.10. Сквозной путь заявка → закупка → оплата → приёмка → склад
уже прогнан на PostgreSQL (deploy/README.md), «Из расчёта» читает Google ключом с сервера.
1. День старта волны назначает владелец. С этого дня новые заявки заводятся только в ERP.
2. Строки, уже начатые в Google (Закупка / Ожидание), доводятся до приёмки там же; пришедший по ним товар
   приходуется в ERP ручным вводом партии на «Складе» (`POST /api/stock/batches`) — переносить строки закупки не нужно,
   в Google это тестовые данные (правило владельца 14.09).
3. Закупщики и кладовщики получают роли в ERP (сотрудники уже заведены с PIN), первая неделя — сверка каждой
   приёмки с бумажной УПД.

## Если ERP встала
- Код: `push.ps1 -Server <IP> -Ref <прошлый коммит>` (коммит в `/opt/erp/app.prev/REVISION`).
- База: `restore.sh <последняя копия>`; движения после копии повторить вручную.
- Вернуться на Google можно только вручную: движения склада, сделанные в ERP после заморозки, перенести в ЦАР/СПИСАНИЕ
  руками. Обратного импорта нет.

## После запуска (не мешает пяти блокам)
- Запись КД на Google Диск: OAuth владельца (`ERP_KD_DRIVE_OAUTH_JSON`, README «Google»). Без него КД только читается.
- Свой домен вместо sslip.io.
