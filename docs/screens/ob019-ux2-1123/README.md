# ОБ.019 — проверка карточки 23.11.2026

Снимки сделаны с настоящими React-компонентами карточки и стилями ERP. Все ответы API заменены локальными
фикстурами. Команды и записи перехватываются, возвращают отказ макета и не выходят в сеть. Снимки подтверждают
вёрстку и отображение состояний; работу ПЛК они не подтверждают.

## Что сохраняем из исходной карточки

- Состояние станка и следующая команда читаются вверху; причина недоступной команды стоит под кнопкой.
- Чертёж связывает длину, зачистку и стягивание с соответствующим концом провода.
- Команды стоят в одной строке, «Стоп» легко найти; цвета полей соответствуют стилю ERP.
- Изменения должны убрать лишние действия из заголовка, отделить необязательное задание и перенести маркировку
  под чертёж без перестройки знакомой оператору карточки.

## Design critique

Знакомый чертёж и строка команд сохранены. В заголовке остались два действия, ручной выбор провода находится
в «Что режем», задание ЭТК вынесено отдельным необязательным блоком. Режимы видны одновременно, маркировка
расположена после длины провода. Состояния готовности, потери связи, аварии и завершения различаются словами,
а не только цветом.

| Проверка | Результат |
|---|---|
| Иерархия | Сначала состояние и команды, затем провод/количество, необязательная ЭТК, геометрия и маркировка |
| Согласованность | Используются прежние стили ERP; сегменты режима соответствуют переключателям стягивания |
| Доступность | Размер новых сегментов 44 px; `:focus-visible` сохранён; поля имеют доступные названия; числа выровнены вправо и используют `tabular-nums` |
| Состояния | При отсутствии связи значения серые с датой; при аварии видны причина и следующее действие; при превышении цели остаток равен 0 |
| Безопасность проверки | Mock-ответы, сетевой доступ ограничен localhost; открытие подтверждения не отправляет POST |

Исправлены два замечания первого прохода: подсказка теперь предлагает выбрать провод **или** задание;
«Проба и поправка» стоит сразу после маркировки, до экспертных групп. Итоговые снимки пересняты и каждый
просмотрен после этих исправлений. Новых критических и существенных замечаний к расположению элементов нет.
На семи сочетаниях размера/состояния: 0 ошибок JavaScript, 0 горизонтального переполнения страницы и окна,
0 POST; высота видимых команд и сегментов — не меньше 44 px (`after-checks.json`). Открытие диалога нового
тиража также отдельно проверено: POST не отправляется.

### Проверка за пять секунд

| Состояние | Всё ли нормально | Что режет / будет резать | Следующее действие |
|---|---|---|---|
| Готовность | Ожидание, связь есть | На станке ПВАМ 0,35, 325 мм; новый провод ещё не загружен | Выбрать провод или задание |
| Пульт открыт | ERP не управляет станком, данные прежние | Последний известный провод показан серым, это не подтверждение текущей работы | Закрыть пульт на ПК |
| Авария | Нет провода | Пуск недоступен; параметры последнего провода сохранены | Устранить причину и сбросить аварию |
| Работа | Режет 37 из 100 | ГР-0007, ПВАМ 0,35, 325 мм | Дождаться конца тиража |
| Завершение | Тираж готов, факт 2056 при цели 2050 | Остаток 0; новый тираж ещё не подготовлен | «Новый тираж», затем проверка и подтверждение |

### UI guidelines audit

Просмотрены изменённые `Ob019Card.tsx`, `Ob019SettingsPanel.tsx`, `Ob019RunJob.tsx`, `Ob019MarkingBlock.tsx`
и `machines.css` по локальным правилам `ui-guidelines-audit`. Новых полей без доступного названия, исчезнувших
обводок фокуса, обработчиков клика на неинтерактивных элементах и неверного диапазона прогресса не выявлено.
Аккордеоны используют нативные `details/summary`, переключатели — кнопки, подтверждение нового тиража — диалог.
Латиница в тексте самой метки допустима: это содержимое для маркиратора, а не англоязычная подпись интерфейса.
Существующее обозначение D54 в блоке поправки относится к прежнему экрану и в этом изменении не добавлялось.

## Воспроизведение

Локальный изолированный harness: `frontend/.ob019-shot/`. Он использует зависимости установленного frontend
и глобальный Playwright. В одном терминале запустить `node frontend/.ob019-shot/serve.mjs`, в другом —
`node frontend/.ob019-shot/shoot.mjs after`. Порт — `127.0.0.1:5197`; производственные серверы не используются.
`settings.json` содержит фиксированные демонстрационные значения, созданные из карты полей текущей базы.
Повторный `fixtures.mjs` обновляет список полей из backend; зафиксированные снимки «до» не перегенерировать.
