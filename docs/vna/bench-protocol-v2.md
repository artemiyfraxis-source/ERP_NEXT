# Протокол рабочего места ВАЦ v2 (vna_control version 2) — контракт

Слайс S0 плана «ВАЦ только через ERP» (19.11.2026). Документ фиксирует **форму** команд и квитанций; хранение,
шаги сессии `purpose='bench'` и миграция — S3, реализация в агенте — S2 (agent 2.10.0). Миграции в S0 нет.

Источник истины по границам — Pydantic-схемы `backend/app/modules/production/vna_bench_protocol.py`
(v1 — `vna_sessions.py`, без изменений). Транспорт, идентичность ПК, журнал, мьютекс прибора, сторож 180 с,
коды HTTP и правила повторной отправки — как в [session-protocol.md](session-protocol.md).

## Принципы

- v2 — надмножество v1. Все операции v1 (`prepare` … `restore`) сохраняют свои аргументы и квитанции, кроме
  `capture`: в v2 он дополнительно получает `screen_hash` и возвращает температуры и `screen_hash`.
- Только типизированные операции. ERP не передаёт SCPI-строки, имена членов COM, скрипты и пути к файлам; агент
  сопоставляет каждой операции свой фиксированный набор вызовов. Неизвестные поля и операции отклоняются
  (`extra="forbid"`, 422).
- Нормы, полосы, шкалы и линии допуска задаёт только ERP. S2VNA — только для просмотра графиков: агент оставляет
  на приборе экран ERP и перед каждым свипом сверяет профиль и экран, отказываясь при расхождении.
- Неизвестное значение датчика — `null`, никогда не выдуманный 0 °C.

## Объявление возможности (heartbeat)

`POST /api/stock/scan/agent/heartbeat`, объект `vna_control`:

```json
{"version": 2, "methods": ["acm"], "ops": ["device_status", "apply_screen", "acm_confidence", "store_memory", "release"]}
```

- `version` — целое 1..100 (как раньше: более новый агент не теряет heartbeat сканеров и принтеров). Команды
  сессий получают только агенты с `version` ∈ {1, 2}; агент v2 продолжает обслуживать сессии v1.
- `ops` — реализованные операции v2 из списка выше, без повторов, до 5. При `version: 1` список обязан быть
  пустым или отсутствовать. Неизвестное имя операции или поле — 422.
- В S0 `ops` проверяется, но не сохраняется: колонка появится миграцией S3, и до неё сервер не выдаёт операции v2.

## Конверт команды

Как в v1, но `"protocol_version": 2` для сессий рабочего места (S3). Операция и аргументы проверяются
`command_args(protocol, op, args)`: операция не из таблицы своего протокола отклоняется.

## Экран (`Screen`)

```json
{
  "split": 8,
  "traces": [
    {"param": "S11", "format": "SWR", "scale": {"pdiv": 0.02, "rlev": 1.0, "rpos": 0}, "hidden": false, "memory": false,
     "limits": [{"kind": "upper", "start_hz": 10000000.0, "stop_hz": 18000000000.0, "start_value": 1.3, "stop_value": 1.3}]},
    {"param": "S21", "format": "MLOG", "scale": {"pdiv": 0.05, "rlev": 0.0, "rpos": 10}, "hidden": false, "memory": false,
     "limits": [{"kind": "lower", "start_hz": 10000000.0, "stop_hz": 18000000000.0, "start_value": -0.3, "stop_value": -0.5}]},
    {"param": "S11", "format": "SMIT", "scale": {"pdiv": 1.0, "rlev": null, "rpos": null}, "hidden": false, "memory": false, "limits": []},
    {"param": "S21", "format": "GDEL", "scale": "auto", "hidden": false, "memory": false, "limits": []}
  ],
  "markers_hz": [1000000000.0, 3000000000.0, 6000000000.0, 12000000000.0, 18000000000.0],
  "title": "КБ1 № 1 — ОТК"
}
```

| Поле | Границы |
|---|---|
| `split` | целое 1..16, код расположения окон S2VNA; агент сверяет прочитанное |
| `traces` | 1..16 графиков; порядок = номер графика на экране (1-based). `param` ∈ S11/S21/S12/S22, повторы допустимы |
| `format` | `SWR`, `MLOG`, `PHAS`, `GDEL`, `SMIT` |
| `scale` | `"auto"` (агент вызывает автомасштаб после каждого свипа) или объект: `pdiv` > 0 (≤ 1e6); `rlev` −1e6..1e6; `rpos` целое 0..10. Для `SMIT` задаётся только `pdiv` (`rlev`/`rpos` = `null`), для остальных форматов — все три |
| `hidden`, `memory` | булевы; `memory` — показывать трассу памяти рядом с данными |
| `limits` | до 20 отрезков: `kind` `upper`/`lower`, `start_hz` < `stop_hz` (0 < f ≤ 1e12), `start_value`/`stop_value` −1e6..1e6. На `SMIT` линий нет |
| `markers_hz` | до 15 частот (Гц) строго по возрастанию; ставятся на каждый график |
| `title` | до 256 символов без управляющих |

Все числа конечные (NaN/∞ отклоняются).

**`screen_hash`** — SHA-256 канонического JSON экрана (`screen.model_dump(mode="json")`, сортированные ключи,
UTF-8, без пробелов; та же функция, что `kit_fingerprint`). Его вычисляет **ERP**; агент не пересчитывает отпечаток,
а хранит в журнале описание экрана под этим ключом и эхом возвращает его, когда прочитанный экран совпал с описанием.

## Операции v2

Каждая успешная квитанция содержит `serial` (живой серийный номер ВАЦ), он сверяется с сессией.

| Op | `args` | `result` сверх `serial` |
|---|---|---|
| `device_status` | `{}` | `name` (строка идентификации S2VNA), `ready`, `warmup_min` (мин с запуска S2VNA или `null`), `temperatures`, `acm` (`null` или `{model, serial, min_hz, max_hz}`), `correction` (`{трасса: код}`, код `^[A-Z?!]{1,8}$`, например `COR`, `C?`, `C!`), `screen_hash` (действующий экран ERP или `null`, если экран изменён/неизвестен) |
| `apply_screen` | `{screen, screen_hash}`; отпечаток обязан совпадать с `screen` | `screen` — прочитанный обратно, `screen_hash`; оба должны совпасть с запрошенными |
| `acm_confidence` | `{profile, module_serial}`; `profile.points` ≤ 4001 | `module_serial`, `frequencies_hz`, `data`, `memory`, `temperatures` |
| `store_memory` | `{screen_hash, traces:[номера графиков 1..16, без повторов]}` | `screen_hash`, `memorized` — те же номера |
| `release` | `{screen_hash}` (`null`, если экран ERP не ставился) | `released:true`, `continuous:true`, `screen_hash` = из `args` |
| `capture` (v2) | аргументы v1 + `screen_hash` | квитанция v1 + `temperatures`, `screen_hash` = из `args` |

`temperatures`:

```json
{"vna_c": [31.2, null], "acm_c": 30.9}
```

`vna_c` — 1..4 датчика ВАЦ, `acm_c` — датчик АКМ или `null`; значения −50..150 °C либо `null`. Правило «±1 °C от
калибровки» и отказ при неизвестной температуре — проверки сервера в S3/S4, схема лишь честно переносит показания.

`acm_confidence` (доверительный тест АКМ: АКМ в состоянии аттенюатора, измеренные S-параметры — в `data`,
хранимые в АКМ — в `memory`):

```json
{
  "serial": "26030095", "module_serial": "26140008",
  "frequencies_hz": [10000000.0, 4507500000.0, 9005000000.0],
  "data":   {"S11": [[0.01, -0.02], [0.02, -0.01], [0.015, 0.0]], "S21": [[0.5, 0.1], [0.4, 0.2], [0.3, 0.3]]},
  "memory": {"S11": [[0.011, -0.019], [0.021, -0.011], [0.014, 0.001]], "S21": [[0.5, 0.1], [0.4, 0.2], [0.3, 0.3]]},
  "temperatures": {"vna_c": [30.0, 30.5], "acm_c": 29.8}
}
```

Отсчёт — пара `[re, im]`. Частоты строго возрастают; наборы трасс `data` и `memory` одинаковы и равны
`profile.traces`; длина каждой трассы = числу частот = `profile.points`; первая/последняя частота совпадает с
`start_hz`/`stop_hz` профиля (допуск 1e-9 отн., 1 мГц абс.); `module_serial` = из аргументов. Предел 4001 точка
держит четыре трассы данных и памяти внутри запроса результата 3 МиБ. Вердикт доверительного теста считает ERP (S1).

## Обязанности агента (S2)

- `apply_screen`: задать графики, форматы, шкалы, линии допуска, маркеры и заголовок; отключить сглаживание,
  временную область и стробирование на каждом графике; прочитать всё обратно. Сравнение с допуском 1e-9 отн.;
  в `screen` вернуть прочитанные значения, округлённые до 9 значащих цифр (так 0.0200000001 возвращается как 0.02).
  При расхождении — ошибка, не квитанция.
- Перед каждым `capture`, `acm_confidence` и `store_memory`: прочитать профиль и экран, сравнить с описанием под
  `screen_hash` в журнале; при изменении (оператор трогал S2VNA) — отказ с ошибкой. Также отказ при коррекции
  `C?`/`C!`, включённом сглаживании/усреднении, смене профиля/сетки или серийного номера.
- `release` завершает управление: непрерывная развёртка, внутренний запуск, COM освобождён; экран ERP и
  калибровка **остаются** на приборе для просмотра. В отличие от `restore`, состояние оператора не загружается.
- Аргументы не содержат путей: файлы состояния и журнал агент выбирает сам.

## Совместимость с v1

- Таблицы `ARGS`/`RESULTS` v1 не изменены; `capture` v1 по-прежнему отклоняет `screen_hash` и `temperatures`.
- Существующие сессии ОТК (protocol_version 1) работают с агентом, объявившим версию 1 или 2.
- Агент версии 3+ сохраняет heartbeat, но команды сессий не получает.
