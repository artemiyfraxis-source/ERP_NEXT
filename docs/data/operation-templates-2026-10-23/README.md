## Как применяется (главная сессия, после релиза ветки — в нём СТО ред. 3 и правила разделов)

1. Резервная копия БД (`deploy/update.sh` делает её сам).
2. Репетиция: скопировать на сервер в `/tmp/tpl/` файлы `apply_templates.py`, `payload.json`, `check.py`,
   `tpl-rehearse.sh`; `sudo -n bash /tmp/tpl/tpl-rehearse.sh`. На копии: `check.py` → запись `--apply` → `check.py` →
   `etk_refresh --dry-run`.
3. Ожидание: `created: 10`, `missing: 0`, `no_row: 0`, `changed` + `unchanged` = 111; кодов в библиотеке +10; один
   запрос пересчёта ЭТК; событий аудита = changed + created.
4. Боевой запуск: `ERP_DATABASE_URL=… PYTHONPATH=/app/backend python apply_templates.py payload.json --apply`.
   Подпись правок — «Аудит ГОСТ Р 23.10.2026». Одна транзакция → одна автоматическая ревизия на карту ЭТК.

Новый код создаётся тем же путём, что «Новая операция» (`create_operation_templates_in`, пустой лист ERP с
категорией из БД.ОП «Название»), затем на него ложится запись (`operation_cards.edit`), событие
`techcards.operation_template_created`. Строку БД.ОП скрипт не создаёт: без строки — `no_row`, ничего не пишется.

## Как откатить

`python apply_templates.py payload.json --rollback ../operation-templates-2026-10-22/templates-after.json [--apply]` —
в одной транзакции удаляет 10 созданных карт (только если после записи их никто не правил: `edited_by` и `saved_by` —
подпись скрипта, иначе отказ целиком) и пишет записи 22.10 (они же — дамп прода до записи, `templates-after-prod.json`
вне git совпадает с ними один в один). Подпись отката — «Откат аудита ГОСТ Р 23.10.2026». СТО откатывается релизом
(ред. 2 — в истории git). Полный откат — резервная копия БД.
