# Аудит шаблонов операций по ГОСТ Р / ГОСТ РВ — 22.10.2026

Комплект ТД (МК, ОК, ВТД, ОК ТК), печатаемый из выпущенных ЭТК, уходит к заказчикам по ГОСТ Р / ГОСТ РВ. Каждая
нормативная ссылка в шаблонах операций и в СТО называет стандарт **и пункт** («ГОСТ 23587-96, п. 5.5»), а не стандарт
целиком. Здесь — след этого аудита: что было, что стало, по каким нормам, как применено и как откатить.
Секретов в папке нет (репозиторий публичный).

## Что проверено

- 112 шаблонов карт операций (БД.ОП, `operation_cards`): резка, зачистка, опрессовка, пайка и лужение, изоляция и
  термоусадка, маркировка, корпуса и фиксаторы, коаксиал. Разбор по группам — `findings/*.md` (A резка, B зачистка,
  C опрессовка, D1/D2 пайка, E изоляция, F маркировка и корпуса, G коаксиал).
- Нормы — только по проверенной карте пунктов `norms-map.md` (каждый пункт сверен с текстом стандарта):
  ГОСТ 23585-79, 23586-96, 23587-96, 23592-96, 23594-79, ГОСТ Р МЭК 61191-4-2019, ГОСТ Р 72182.2-2025, ГОСТ 2.414-75,
  ГОСТ 3.1129-93. Ссылки на целые стандарты, IPC и «согласно КД» как основание убраны.
- Правила текста шаблона: переходы — повелительное наклонение («Отрезать…», «Проверить…»), без заголовков капсом,
  допуск пустой — «-», допуск по документации изготовителя — «по ДИ», по чертежу — «по КД».
- СТО ФРАК-001-2026 переиздан как **редакция 2** (`sto-rev2-notes.md`): у каждой строки дефекта есть «Основание»
  (`basis`), у каждого раздела — `norms` (стандарт, пункты, предмет). Файл — `backend/data/sto-frak-001-2026.json`.

## Файлы

| Файл | Что это |
|---|---|

## Как применяется

Шаблоны пишутся **после** релиза этой ветки (в нём — СТО ред. 2 и печать норм), одной транзакцией:

1. Резервная копия БД (`deploy/update.sh` делает её сам).
2. Репетиция на копии прод-БД: `ERP_DATABASE_URL=<копия> python apply_templates.py templates-after.json` без `--apply` —
   проверяет каждую запись (`normalize_record_edit`) и откатывает; печатает по кодам changed / unchanged / missing.
3. Боевой запуск: то же с `--apply`. Скрипт правит карту по коду (`operation_cards.edit`), пишет событие аудита
   `techcards.operation_record_edited` на каждый изменённый код. Все правки — одна транзакция, поэтому одно
   обновление библиотеки даёт одну автоматическую ревизию ЭТК на карту (ETK_AUTO_REVISION).
4. Сверка: `unchanged` + `changed` = 111, `missing` = 0.
5. Шаблон `PRS_CAP` (колпачок на жилы) удаляется из библиотеки (владелец 22.10.2026: «можно удалять, для коаксиалов уже есть другая») — после проверки на копии, что ни одна ЭТК его не использует; крышка углового коакс-разъёма берёт `PRS_CAP_COAX`.

Правка ложится по коду на **все** варианты сторон A/B этого кода (`operation_cards.edit`); у 12 кодов со сторонами тексты A и B в аудите одинаковы.

## Как откатить

Записать `templates-before.json` назад тем же скриптом. Формат «до» другой (`{id, code, side, document}`), поэтому
перед запуском его приводят к формату скрипта: по одной записи на код (у кодов со сторонами — сторона A) взять
`{"code": code, "record": {name, safety, defects, revision, steps, tooling}}` из `document` и сохранить списком; затем
`python apply_templates.py rollback-payload.json` (репетиция) и с `--apply`. Дополнительно — резервная копия БД,
снятая перед записью. Точный откат вариантов сторон (до аудита у `SDR_COAX_housing` тексты A и B различались) и
удалённого `PRS_CAP` — только из этой резервной копии.

## Код этой ветки

- `td_sto.py`: `sto_norms(code)` — нормы раздела(ов) СТО операции (совмещённые коды склеивают нормы разделов, документ
  один раз, пункты по порядку без повторов; общая пайка 4.4 — нормы 4.4.2 и 4.4.3); `sto_sections` печати несёт `norms`.
- Печать: МК (графа «Документы» — стандарт и пункты), ОК (строка «Технические требования — по …»), ВТД (СТО с ревизией и
  каждый стандарт, названный в операциях, с использованными пунктами), СТО (колонка «Основание», нормы под заголовком раздела).
- `etk_builder`: допуск реза подставляется и в шаг «тестовый рез» с допуском «-»; `coax.py`: крышка с обжимом берёт
  карту `PRS_CAP_COAX`; `etk-marking.json`: блоки меток переписаны по правилам аудита.
