# Оборудование — итоговые названия 12.11

Подготовлены решения по оставшейся части сверки 05.11 и проект скрипта для последующего применения. В прод ничего не записывалось; коммитов, отправки ветки и PR нет.

Исходник: [сверка 05.11](Оборудование%20—%20сверка%20названий%2005.11.csv). Результат: [итоговый CSV](Оборудование%20—%20итоговые%20названия%2012.11.csv). Скрипт: [переименование 12.11](Оборудование%20—%20переименование%2012.11%20запись%20в%20прод.py).

## Охват и формат

84 исходные строки: «Оборудование» и «Инструмент» со статусами «вероятно»/«неясно», а также ранее отложенные ОБ.024.2/.4 и ОБ.105. Объединённая строка ОБ.024.2/.4 разделена: результат — **85 строк, 120 инвентарных единиц**. «Матрицы» исключены. Уже применённые 11.11 строки не включены.

CSV: UTF-8 с BOM, разделитель `;`, окончания LF. `inv` содержит отдельный номер либо полный перечень единиц одной модели; номера с историческим написанием ОБ.79, ОБ.80, ОБ.81–84 сохранены. Колонки:

| Колонки | Смысл |
|---|---|
| `inv`, `type` | Инвентарные номера и тип исходной сверки |
| `current_name`, `article`, `current_maker` | Ожидаемые исходные значения для защитных проверок |
| `final_name`, `final_maker`, `role` | Итоговое название, изготовитель/марка и роль |
| `confidence`, `basis`, `source_url` | Степень подтверждения, основание и проверенные ссылки |

| Достоверность решения | Строк |
|---|---:|
| подтверждено — точная модель на странице изготовителя или в его документе, в том числе на зеркале | 27 |
| по описанию — карточка поставщика либо подтверждение части составной записи | 17 |
| только нормализация — без установления точной модели | 41 |

Все 52 непустых артикула исходной выборки проверены поиском; разделённые прессы дают 53 итоговые строки с артикулом. В 32 исходных строках артикул отсутствует. Отсутствие результата поиска не доказывает отсутствия изделия: близкие модели и их параметры не подставлялись. При недоступности источника пробовались альтернативные страницы и Web Archive; недоступность отмечена в основании.

«Подтверждено» относится к идентификации по документам, а не к осмотру физического экземпляра. Ранее записанные марки у неидентифицированных моделей сохранены как инвентарные данные с явной оговоркой в `basis`. Неизвестные марки не назначены; для L-107 не подтверждена Lead pack, для KS-4C не подтверждён изготовитель вместо поставщика Provod-Cabel — итоговые поля пустые.

## Принятые решения

- ОБ.83 KM-PO: **осушитель сжатого воздуха рефрижераторный**, а не жидкостный охладитель. Основание — [руководство KraftMachine](https://static.insales-cdn.com/files/1/726/39412438/original/km_po_osushiteli_rukovodstvo_po_ekspluatacii_kraftmachine_26_03_25.pdf). Числовое исполнение не додумано.
- ОБ.102 ZCUT-RT660: **автомат печати и наклейки этикеток на провод с обёртыванием**. [Страница Yuanhan](https://www.ksyuanhan.com/product/zcut-rt660shishijuantiebiaoqianji.html) подтверждает наклеивание этикеток, а не печать трубчатых маркеров.
- ОБ.024.2: пресс MHF-4 под кабель 1,37 мм; ОБ.024.4: пресс MHF-1 под кабель 1,78 мм. Разные назначения подтверждены отдельными записями `backend/data/reference-mirror/БД.ОБ.tsv`. Для ОБ.024.4 исправлено ошибочное общее исходное имя сверки: его старое значение заканчивается `MHF-1 (1.78)`. Страница Sinrad подтверждает семейство SR-IPEX; фактическая оснастка взята из инвентарных записей. U.FL и MHF не отождествляются; неподтверждённый тип привода в итоговом имени не указывается.
- ОБ.105: **«Анализатор цепей векторный двухпортовый 1–8800 МГц»**, изготовитель **ARINST**, по заданию и [руководству изготовителя](https://arinst.net/files/Manual-Two-port-vector-network-analyzer-ARINST-VNA-DL-1-8800MHz_RUS.pdf).
- ОБ.028 ST-6L/SAL-800G1: **сушилка бункерная для полимерных материалов с вакуумным загрузчиком**. Загрузчик SAL-800G1 подтверждён; ST-6L остаётся неидентифицированной. Сохранена одна учётная единица: данных для создания двух физических единиц нет.
- Найдены ранее не подтверждённые AIRLINE ATBN052, Crown WL-IDC, CT Brand CT-53D, DAYTON ST-1500B, Sinrad SR-2T, КВТ ПКП-10к и ЗУБР ЗТШМ-150. Точные основания и ссылки находятся в соответствующих строках CSV.
- Корректные названия сохранены, в частности у сверлильного станка ОБ.013, источника питания ОБ.044, зарядного устройства ОБ.088, трансформатора ОБ.063 и компрессора ОБ.037. Артикулы не исправляются этим пакетом, включая кириллицу/латиницу, суффиксы и составные обозначения.

Без точного подтверждения модели оставлены B25H064, BZW-200+H, BY-27BX, HRSU-400LL, PH-21C, AM901, RS1010Z, SR-16M и SR-IPEX-L. Новые характеристики этим изделиям не назначены.

## Роли

Операционные: **50 строк / 65 единиц**. Обеспечивающие: **35 строк / 55 единиц**. Назначение взято из подтверждённого описания, а при его отсутствии — из исходного реестра.

Компрессоры, ресиверы, осушитель, чиллеры, сушилки сырья, смеситель, дробилка, питание рабочих мест, общие слесарные наборы, отвёртки и ремонт пресс-форм отнесены к обеспечивающим. Сварочный аппарат SZ-GCS16 обслуживает пресс-формы; штатив Dremel поддерживает инструмент. Резка, зачистка, опрессовка, пайка, маркировка и контроль изделий — операционные функции.

Источники питания ОБ.041/.044 и тепловизор ОБ.045 оставлены обеспечивающими по исходной ведомости: использования именно для контроля изделия данные не устанавливают. Общий инструмент без связи с операцией не объявлен её исполнителем. Скрипт откажет всему пакету, если обеспечивающая модель уже связана с операцией/шаблоном; такие связи автоматически не удаляются. Это проверка фактической БД перед применением, а не повод угадывать её состояние.

## Скрипт и отсутствующие ячейки ОБ.105

Проект основан на скрипте 11.11: поиск по `Инв. номер`, проверка каждого старого значения, полного состава модели, UUID, связей и посторонних записей. Значение, уже равное целевому, считается применённым; любое третье значение отменяет пакет. Артикулы, типы, инвентарные номера и UUID не меняются. Допустимый исторический тип `Оборудование (ПР)` сохраняется. Существующий `obType` должен совпадать с `Тип`: расхождение отклоняется до записи, чтобы сервис синхронизации не исправил его автоматически.

`_edit_in` **не умеет добавить** отсутствующие `Наменование`/`Производитель` в `ob`: этих полей нет среди разрешённых отсутствующих ключей. `ob` также не поддерживает пользовательский «+ Столбец». Поэтому после полной предварительной проверки скрипт добавляет только недостающие пустые ключи ОБ.105 через `uow.tech_operations.save`, сохраняя прежние UUID и подпись. Затем записывает значения обычным `_edit_in` с `old=""`. Добавление ключей отмечается в аудите отдельно от замены пустого значения. Это ремонт ячеек конкретной строки внутри той же транзакции; схема приложения не меняется. `import_rows` не используется: его ключ оборудования — `baseValue`, и он самостоятельно управляет транзакцией.

Роль и `role_confirmed` задаются через `uow.equipment.set_role`. Обновление производных подписей БД.ОП, аудит и запрос обновления ЭТК входят в общий commit. Исторические ЭТК и шаблоны не переписываются. В `dry` изменений, flush, аудита и commit нет. Исполняемая точка входа требует PostgreSQL; SQLite используется только для проверки функции обработки на тестовых данных.

Порядок будущего запуска приведён в docstring: репетиция на копии без refresh-worker, затем **dry → backup-now → apply → dry**. Перед apply требуется остановить конкурентные записи справочника и дождаться текущих запросов; apply дополнительно блокирует пять таблиц. Конкретная команда резервного копирования сохранена из скрипта 11.11. Производственный запуск в эту работу не входит.
