# Читаемые карты операций — ревью генератора ЭТК 23.11.2026, срез 2

Владелец 23.11: «тут тоже нужна проработка текстов, это не читаемо». Ревью генератора (выгрузка ЭТК прода 23.11) нашло
167 операций в 68 ЭТК с шагом длиннее 300 знаков (несколько независимых проверок и ссылок в одной строке) и 28 операций
цветовой маркировки с псевдошагами «Вход:» / «Результат:» и словом «BOM». Этот срез переписывает тексты **шаблонов**:
одно действие — один шаг, каждая проверка — своя строка «Контроль», ссылка на пункт стандарта — в графе «Допуск» рядом
с требованием. Все числовые пределы, единицы, пункты стандартов, объём контроля, инструмент и требования безопасности
сохранены; название, безопасность, дефекты, ревизия и оснастка карт не меняются.

## Как применять (координатор; прод — только с разрешения владельца)

1. Резервная копия; репетиция на копии прод-БД: `--plan-out plan.json` → в плане по каждому коду `changed` /
   `unchanged` / `drifted` / `protected` / `missing`, режим, хеш, подписи и время правки.
2. `--expect plan.json --rollback-out readability-rollback.json --apply` пишет ровно этот план (иначе — отказ, ничего не
   записано). Файл отката пишется до фиксации и не перезаписывается.
3. Запись шаблона ставит стандартный запрос обновления ЭТК (слушатель `etk_refresh`); выданные ЭТК получают ревизии
   только через это обновление и `ETK_AUTO_REVISION`. Запускать в общем окне пересборки после среза 1 (одна ревизия на
   ЭТК), не отдельно.

Защиты: пишется только шаблон с id из payload, чьё содержимое равно `expected_before_hash` (именно из него собраны ЭТК
прода; хеш — нормализованная запись «название, безопасность, дефекты, ревизия, шаги, оснастка») и на котором только
подписи поставок (`TRUSTED_AUTHORS`). Иное содержимое — `drifted`, правка человека — `protected`; оба не трогаются.
Откат восстанавливает колонки шаблона, только если он всё ещё ровно такой, как записан. Откат `CTRL_VSWR_coax` держится
только до следующей выкатки с этим сидом ERP (сид снова запишет свой лист) — для полного отката нужен и откат сида.

## Сиды

- `techcard-library-erp.json`: `CTRL_VSWR_coax` и `MARK_CONN_PAINT` — новое содержимое, ровно `after_hash` (сид ERP и
  есть поставка прода). **`CTRL_VSWR_coax` на проде — лист поставки ERP без правки записи, поэтому сид релиза сам
  обновит его при выкатке** (как при 18.11): тогда скрипт покажет `unchanged`. Скрипт пишет такой шаблон тем же листом
  сида (подпись поставки ERP), а не правкой записи, — следующий сид остаётся хозяином карты. `MARK_CONN_PAINT` на проде
  создан поставкой маркировки 16.11 (её подпись) — сид его не трогает, меняет только скрипт.
- `techcard-library.json` не меняется: это снимок БД.ОП-ТК SUPPLYMAP (714 шагов, `test_operation_cards`), он кладётся
  только в пустую библиотеку; прод ушёл от него поставками 22.10/23.10. `STRIP_COAX_auto` на проде меняет только скрипт.

## Не вошло

- `backend/data/etk-marking.json` (хлястик, 6 операций) — шаги маркировки строит `etk_marking`, не шаблон.
- Псевдошаги «Вход:» / «Результат:» есть ещё в карточках сида ERP, но в ЭТК прода этой выгрузки они не попадают:
  у `PRINT_MARK_LABEL` / `INS_MARK_LABEL` (по 36 ЭТК 708К.) шаги заменяют короткие карты сборки, кодов
  `STRIP_FAKRA_ST/RA/BH`, `STRIP_HFM`, `PRINT_MARK`, `MARK_CONN_LASER`, `MARK_CONN_TAPE` в ЭТК нет. Длинные шаги в
  базовом сиде — `STRIP_COAX_hand`, `INS_RJ_cat5`, `INS_RJ_cat6/7`, `SEAL` (в ЭТК прода нет).
- Семантическая сверка старых и новых строк технологом (план, раздел «Tests»).
