# ОБ.099 — полная карта штатной программы BZW2.5 пресса BZW (18.11.2026)

Станок: ОБ.099, пресс для обжима клемм BZW, модель 4T (`configuerother.Type = 4T`). Сервопресс с ножной педалью,
световой завесой и защитным кожухом. ПЛК Omron CP2E-N20DT-D, вер. 01.07. Монитор усилия обжима OES CFM2103.
Производитель станка и программы — 江苏博之旺自动化设备有限公司 (Changzhou), отсюда «BZW». Экран «О программе»
показывает номер оборудования и версию программы ПЛК (DT5128).

Документ нужен, чтобы ERP заменила BZW2.5 на этом прессе. Проект замены —
[`ob099-erp-control-design-2026-11-18.md`](ob099-erp-control-design-2026-11-18.md). Сеть, БД и журналы описаны в
[`ob099-bzw-press-probe-2026-11-18.md`](ob099-bzw-press-probe-2026-11-18.md).

Как получена карта. Разбор шёл только на чтение. Файлы скопированы с ПК .82 в локальную временную папку, на станке
ничего не запускалось. В ПЛК и MySQL ничего не писалось, BZW2.5 и ForceView не перезапускались.
- `BZW2.5.exe` — .NET Framework 4.6.2, WinForms (DevExpress 13.1, DotNetBar). Имена классов и методов зашифрованы
  SmartAssembly, строки открыты. Декомпилирован ILSpy (ICSharpCode.Decompiler 9.1).
- Зашифрованные имена восстановлены автоматически по свойству `Name` элементов экрана: у полей и кнопок оно почти
  всегда равно адресу ПЛК (`D5008`, `btn_H6000`, `btnW6007`, `checkH6114`). Имена обработчиков восстановлены по
  подпискам на события.
- В поставке есть `BZW2.5.pdb` (отладочные символы). Он дал исходные имена файлов: `FrmMain`, `Form1…Form13`,
  `FormOES` и др. Номера методов после шифрования перемешаны, поэтому PDB использован только как список файлов.

Статусы:
- **проверено** — значение прочитано по FINS 18.11 и совпало с ожидаемым;
- **из кода** — привязка элемента экрана к адресу взята из декомпиляции;
- **предположение** — вывод по косвенным признакам;
- **у станка** — подтвердить на прессе (сводка в §9).

## 1. Связь и протокол

| Что | Значение | Статус |
|---|---|---|
| Транспорт | FINS/UDP, ПК 192.168.250.115 → ПЛК 192.168.250.1:9600. Библиотека HslCommunication `OmronFinsUdp`. `SA1` (узел ПК) берётся из конфига | проверено |
| Слова | u16. Двойные слова (`DT…`) — u32, **младшее слово первым** (`DataFormat=CDAB`) | проверено (DT5108 = 99999) |
| Строки | ASCII, 2 символа в слове, старший байт — первый символ (`IsStringReverseByteWord=false`). Поле 10 слов = 20 символов, дополняется `\0` | проверено (D5540) |
| Области | `D` — DM; `H` — HR, сохраняется при выключении (опции/режимы); `W` — WR, рабочие биты (кнопки, статусы). Биты пишутся адресом `H60.07`, `W84.12` (FINS 01 02, битовая область) | из кода |
| Коды областей FINS для своей программы | DM слово 0x82; HR слово 0xB2, бит 0x32; WR слово 0xB1, бит 0x31; CIO слово 0xB0, бит 0x30 | справочник Omron |

**Цикл обмена.** Один поток с паузой 50 мс. Если в очереди есть команда, поток выполняет её. Иначе читает
следующий блок опроса.
- Очередь — 16 строковых слотов `Commdtxt…Commdtxt15` вида `адрес;тип;значение`. Типы: 0 u16, 1 u32, 2 float,
  3 бит, 4 «прочитать N», 5 строка ASCII. Значения через запятую — запись массива.
- При первой ошибке связи поток останавливается. На экране появляется «PLC communication abnormal, please restart
  the software!». Само программа не переподключается, только через меню «Повторное подключение».

| Блок опроса | Как читается | Что в нём |
|---|---|---|
| `D5005×80` | u16, D5005…D5084 | экран/режим, параметры рецепта и станка (§3.2) |
| `D5100×45` | **u32 ×45**, DT5100…DT5188 (индекс i → DT(5100+2i)) | счётчики, ресурс инструмента, позиции (§3.3) |
| `H60×2` | u16, H60, H61 | опции и режимы (§3.4) |
| `W80×5` | u16, W80…W84 | W80 — аварии (§5), W83/W84 — статусы (§3.5) |
| `W61×9` | u16, W61…W69 | W66 — копия входов X, W68 — копия выходов Y (§3.6) |
| `W101×8` | u16, W101…W108 | «Состояние оборудования», коды LS1–LS5 (§3.6) |
| `D5500/5510/5520/5530/5540 ×10` | строки | задание: изделие, провод, клемма, аппликатор, номер оборудования (§3.1) |
| `D7000×8000` | u16 по запросу (экспорт) | таблица обучения сервопривода (§4.4) |

**Строки задания BZW2.5 читает только один раз**, в первом проходе после старта. Дальше цикл идёт по блокам 0–5.
Если строки поменять снаружи, экран и журнал BZW2.5 покажут старые значения до перезапуска (из кода). Отсюда расхождение
`paneldata` и ПЛК, найденное 18.11 при разборе.

**Типы кнопок в BZW2.5:**
- **Удержание** (`MouseDown` → true, `MouseUp` → false). Бит держится, пока нажата кнопка. Своя программа обязана
  сама снять бит.
- **Переключатель** (`Click`): программа пишет значение, обратное текущему состоянию на экране. Состояние приходит из
  опроса H60/H61.
- **Импульс** (`Click`): true и сразу false двумя слотами очереди. Импульс длится один цикл, примерно 50–100 мс.
- **Число**: ввод с экранной клавиатуры, масштаб, запись.

### 4.2 Загрузка рецепта («Техпроцесс → Открыть → Загрузить», FormCraftsOpen)

1. Строка `craft` выбирается по `ProductModel`.
2. Собирается 25 команд в порядке таблицы выше: строки, D5006, скорости, задержки, DT5114, DT5110, DT5124, D5021,
   DT5118, D5036, D5052–D5050, биты H60.
3. Команды уходят в очередь по одной с паузой 100 мс. Подтверждения записи и обратного чтения нет: ошибка связи
   просто останавливает поток.
4. В MySQL `paneldata` записываются значения рецепта, флаги `LoadCraft=true` и `NewCraft=false`, имя рецепта
   показывается в рамке. Экран переходит на «Производство» (D5005 = 3).

`Craft_Save`.

### 4.3 Сохранение, создание, удаление

- **Сохранить** (`UPDATE Craft SET …`) и **Сохранить как** (`insert into Craft …`) записывают снимок текущих значений
  из опроса ПЛК: D5006…D5052, флаги H60 и счётчики DT5110/DT5114.
- При смене рецепта с несохранёнными изменениями FormSave спрашивает: «Сохранить», «Сохранить как»,
  «Не сохранять», «Отмена».
- **Создать** (NewBuildCrafts): «Параметры по умолчанию» или «Копировать параметры из xx». Новый рецепт только
  создаётся в БД, в ПЛК ничего не пишется.
- **Удалить** — `DELETE` строки после подтверждения.
- Истории изменений нет: кто и когда менял рецепт, не хранится.

### 4.4 Таблица обучения сервопривода D7000×8000

- **Экспорт** (Form6) читает D7000…D14999 и сохраняет в txt одной строкой через запятую.

## 6. Монитор усилия OES CFM2103

**Подключение.** BZW2.5 работает с CFM через SDK OES (`oes.cfm.dll`, `Oes.CfmDevice.dll`, `oes.lib.dll`) по TCP:
Lantronix 192.168.250.50:10001. Параметры — в `configuration/1.config` (`CfmRegistry`: `ConnectionType=1`,
`ComPort=COM3`, `RangeUnits=LB`).
- Соединение одно и постоянное. Второй клиент к .50:10001, пока работает BZW2.5, не подключится (предположение по
  Lantronix в режиме одного соединения).
- `Assemblies/language.db` — переводы интерфейса SDK OES (854 ключа: en/es/zh/de/tr/pl/ja). `configuration/users.db`
  — БД пользователей SDK (зашифрована, не читалась). `TempCfmLogs/` — отладочные журналы SDK со времени пусконаладки
  (2023, сначала USB/COM3).

**Ответ на каждый цикл** (`ICurveResponse`, канал 1):
- `ActPeak` — пиковое значение;
- `TestResult` (`GrossCDA` = брак по отклонению кривой);
- `Mode`: NoLearn, Learn, LearnFail, Run;
- счётчики `CtrPass`, `CtrFailGross`, `CtrFailSigma`.

Цвет поля «CFM» на Form3: жёлтый — обучение, красный — ошибка обучения или GrossCDA, зелёный — годно. Рядом график
кривой и тренд (`pnlGraph`, `pnlTrend`).

**Поштучная запись — журнал `D:\BZW\logs\yyyyMMdd.txt`.** Строка пишется, когда в режиме Run изменился любой из трёх
счётчиков CFM (то есть один раз на цикл). Нужно `OESLog = 1`.

```
ном.оборуд.   изделие   провод   клемма   аппликатор   [код скана]   ActPeak   yyyy/MM/dd <день недели> HH:mm:ss   OK|NG
```

- Поля 2–5 берутся из переменных BZW2.5, заполненных при старте и загрузке рецепта (см. §1).
- Код скана есть только в режиме сканера (H61.14 и `Scanner_Hangtian`).
- **NG ставится только при `GrossCDA`. Брак по сигме (`CtrFailSigma`) записывается как OK** — для ERP нужно брать
  счётчики, а не только флаг.
- Единицы `ActPeak` не подтверждены — у станка.

Запасной журнал без CFM (`Log = 1`): файл `yyyyMMddHHmmss.txt` на сеанс, строка на каждое изменение счётчика партии,
пик «-», всегда OK. Сейчас выключен (`Log = 0`).

Отдельно BZW2.5 считает `PlLiang_OES` — число циклов CFM с начала сеанса.

**Сигнал брака в ПЛК.** BZW2.5 не передаёт ПЛК результат CFM: брак попадает в ПЛК через вход (X7 «Авария по
давлению», предположение) → W80.03 и стоп по D5022.

**Обучение.** Кнопка «Обучение» (W60.15) → ПЛК подаёт Y1 «Обучение усилия» на CFM (предположение) → X8 «Обучение
завершено».

**Настройки канала CFM** (FormOES; пишутся в прибор через SDK, в ПЛК не идут):
- **Обучение:** усиление (`LearnGain`); макс. допуск обучения; мин./макс. число циклов обучения.
- **Анализ:** целевая повторяемость (`ART_Rate`); перерасчёт пределов (`ART_Recale`); процессное отклонение
  (`MaxProcDev`).
- **Зоны:** CMM E1–E3 (`CMMR1–3`, включение `CMM_Enabled`); WR1–3; CR1–3 (компенсация R1L…); VR1–VR4; CDA-L.
- **Захват сигнала:** калибровка (`AlignmentHeight`, наклон); порог старта (`StartLevel`); фильтр; предзапуск
  (`PreTrigger`); длительность (`Duration`).
- Вкладка «Загрузка конфигурации».

## 7. Пользователи, права, языки, защита

- **Пользователи и группы** — MySQL `operator`, `rightsgroup`, `view_operator` и связи прав (DAL `OperatorService`,
  `RightsGroupService`). Права — это доступность пунктов меню для группы, плюс флаги рецептов (`Craft_*`) и право
  «Снятие аварии». Сейчас один пользователь и одна группа (admin / Administrator). Пароли в отчёт не выводились.
- **В окне снятия аварии зашит сервисный логин производителя**, который проходит мимо таблицы пользователей. Логин и
  пароль в документ не переносятся.
- **Временная блокировка запуска.** При старте BZW2.5 читает дату окончания из `C:\WINDOWS\wins.txt`. Если файла нет
  или дата прошла, программа требует 12-значный код производителя (на основе даты). Сейчас срок — 06.06.2053, риска нет.
- **Языки:** тексты зашиты в код по индексу `language.LanguageID` (0 中文, 1 English, 2 日本語, 3 한국어, 4 French,
  5 Русский). Русский перевод частичный. В ERP подписи берутся из этого документа.
- **Сканер кодов «Хантянь»:** TCP-клиент на 192.168.10.79:1024. Выключен (`Scanner_Hangtian = 0`), а адреса из сети
  192.168.10.x на ПК нет.

## 8. Что BZW2.5 не делает (и должна делать ERP)

- Нет истории рецептов и авторства изменений. Нет проверки записи обратным чтением.
- Загрузка рецепта перезаписывает наработку ножей: счётчик привязан к рецепту, а не к аппликатору.
- Нет связи с заданием и заказом. Модель изделия — свободная строка, а у загруженных сейчас рецептов провод,
  клемма и аппликатор равны «A».
- Брак по сигме CFM в журнале записан как OK. Поля журнала могут быть устаревшими после внешней записи строк.
- Нет оператора в поштучной записи и нет учёта простоев.
