# ОБ.099 — управление прессом BZW из ERP вместо BZW2.5: проект (18.11.2026)

Задача владельца (18.11): «готовь переделанную прогу: посмотри, что умеет штатная, и как всем мы должны управлять с
ERP — и не только через техкарты, и если я вне проекта захочу».

Основа — полная карта штатной программы [`ob099-bzw25-full-map-2026-11-18.md`](ob099-bzw25-full-map-2026-11-18.md)
(далее «карта», §N — её разделы). Здесь решения и порядок перехода. Кода ещё нет. Схема БД ниже — предложение, её
надо сверить с модулями `equipment_setup` (версии рецептов `equipment_setup_recipe_versions`, пробные замеры) и
`references` (`equipment_units`, `equipment_applicators`).

## 0. Главное

- **Ход пресса делает только педаль оператора** (X2/X3), при закрытом кожухе (X11) и световой завесе (X4). ERP не
  делает удар удалённо: такой команды в ПЛК нет, и мы её не добавляем.
- ERP может:
  - ставить задание: рецепт, строки, план и партию;
  - включать и выключать режим «Работа» (H60.07);
  - делать сброс и квитирование;
  - обнулять счётчики и ресурс инструмента;
  - читать всё состояние и поштучный результат CFM.
- **Ручные перемещения** (ползун ▲/▼, цилиндры, калибровка, обучение позиций, импорт таблицы обучения) — только с ПК
  у станка, с удержанием кнопки и контролем связи (§d).
- **Один управляющий клиент.** FINS/UDP технически позволяет второму клиенту читать вместе с BZW2.5. Писать
  одновременно двоим нельзя, а CFM по Lantronix держит одно соединение. Поэтому на этапах 0–1 ERP только читает, а с
  этапа 2 агент ERP полностью заменяет BZW2.5 и BZW2.5 закрыта.

## Архитектура

- **Агент станка на ПК .82** — служба Windows рядом с BZW2.5, по образцу агента печати склада. Агент:
  - говорит с ПЛК по FINS/UDP (192.168.250.115 → .1:9600);
  - на этапах 0–1 читает журнал `D:\BZW\logs` и MySQL `bzw2.5` под `erp_ro`;
  - с этапа 2 сам работает с CFM: Lantronix .50:10001 через SDK OES `oes.cfm.dll` (.NET, нужна лицензия или
    согласие OES) или по разобранному протоколу CFM;
  - держит связь с ERP: исходящее HTTPS, команды забирает сам, на ПК не открывается ни одного входящего порта;
  - хранит очередь событий локально (SQLite). Пропадёт сеть — поштучные записи не теряются, а досылаются по номеру.
- **Карта адресов** — один файл данных в агенте. В нём адрес, тип, масштаб, предел и права из карты §3. В ERP
  уходят уже смысловые поля («высота обжима, мм»), а не адреса.
- **Цикл чтения** — как у BZW2.5, но реже: состояние раз в 200–500 мс, строки задания после каждой записи.
- **Запись по шагам:**
  1. Агент сверяет версию задания.
  2. Пишет значение.
  3. Читает обратно.
  4. Сравнивает и сообщает в ERP: «записано и подтверждено» или «расхождение».

  Подряд записываются только значения, обратного чтения после каждого ждать не нужно.

## a) Задание из операции ЕТК

1. Оператор у пресса (или мастер) открывает задание операции «Обжим» на ОБ.099. Операция ЕТК знает клемму (артикул
   контакта), провод (марка, сечение, цвет), аппликатор (`equipment_applicators`) и количество.
2. ERP выбирает рецепт по ключу (клемма, сечение провода, аппликатор) на этом прессе (`equipment_units` ОБ.099).
   - Найдено несколько версий — берётся утверждённая последняя.
   - Не найдено — задание не стартует: «Нет рецепта для 61117-4 / 0,5 мм² / А-12 на ОБ.099 — создать».
3. **Проверка аппликатора.** Оператор сканирует или выбирает установленный аппликатор. Если он не совпадает с
   операцией — блок.
4. **Загрузка в ПЛК** (этап 2, §4.2 карты, но с проверкой). Агент пишет:
   - D5500 — код задания/операции (до 20 символов), D5510 — провод, D5520 — клемма, D5530 — инв. номер
     аппликатора, D5540 — инв. номер пресса;
   - параметры рецепта и биты H60;
   - **DT5110/DT5114 не пишет никогда** (§f).

   Затем читает всё обратно и сверяет. Пока всё не подтверждено, «Запуск» недоступен.
5. **План.**
   - Записать DT5102 (партия) = количество задания и DT5100 (общий) = количество задания (или план смены).
   - Обнулить счётчики импульсом W60.05 — только после подтверждения у станка, что он обнуляет именно эти счётчики
     (карта §9 п.1).
   - Начальные значения DT5104/DT5106 запоминаются в задании.
6. **Запуск:** H60.07 = 1 (режим «Работа»). Удары делает педаль. Каждый цикл CFM — запись о качестве (§e), прогресс
   задания = число годных.
7. **Конец:** партия выполнена (W83.03) или оператор нажал «Стоп» → H60.07 = 0. Задание закрывается с итогом:
   годных, брака, пиковые значения, время, простои. Брак не засчитывается в выпуск.

## b) Ручной режим вне проекта

Владельцу нужно работать на прессе без заказа: пробные обжимы, наладка, свои нужды, «просто сделать 200 штук».

- Кнопка «Ручная работа» на экране станка.
- Оператор выбирает **сохранённый рецепт** или **клемму + провод + аппликатор** (тогда ERP подбирает рецепт как в
  (a)). Если рецепта нет — **черновой рецепт** с обязательной пробой. Вводит количество (можно «без ограничения») и
  комментарий «зачем».
- Дальше всё как в (a): загрузка с проверкой, план, «Работа», поштучный CFM, счётчики инструмента.
- Учёт — в **журнале ручной работы**, вне проектов и КБ: станок, оператор, рецепт и версия, аппликатор, клемма и
  провод, количество годных и брака, время, комментарий. Остатки склада ручная работа сама не списывает. Списание
  клемм — отдельным действием «Списать на ручную работу» с выбором партии.
- Ручную работу можно потом привязать к заданию или КБ (например, наладка перед заказом) — с аудитом, без
  перезаписи исходных записей.
- **То же требование для ОБ.019** (резка и зачистка с лазерной маркировкой) **и маркировщиков Godex**. Для них нужен
  такой же экран «Ручная работа»:
  - **ОБ.019:** длина, зачистки, текст маркировки, количество → тот же журнал ручной работы со счётчиком D641/
    тиража.
  - **Godex:** ручная печать произвольной надписи по откалиброванному профилю. Партия печати без задания, с причиной
    и учётом расхода ленты. Пробная печать калибровки уже есть, это её продолжение.

  Журнал ручной работы — общий для всех станков. В схеме: тип станка + параметры задания в JSON с версией формата.

## c) Библиотека рецептов в ERP вместо таблицы `craft`

- **Рецепт** — это ОБ.099 + ключ (клемма, сечение или диапазон сечений, аппликатор) + понятное имя. Версии
  только добавляются, удалённых и переписанных нет — как уже сделано в `equipment_setup_recipe_versions`.
- **Поля версии** (типизированные, с единицами и пределами из карты §3.2–3.4):
  - высота обжима, мм (в пределах D5047…D5046), допуск, мм;
  - скорость обжима и предобжима;
  - задержки подачи и резки, интервал резки, время удержания;
  - позиция предобжима DT5124 и DT5118 (как «параметр B», пока смысл не подтверждён);
  - времена зажима и проталкивания D5050–D5052;
  - опции подачи, резки, контроля CFM, предобжима, проталкивания (H60.00/.01/.02/.08/.14);
  - профиль CFM (§6 карты) — ссылкой на сохранённые настройки канала, когда агент начнёт писать их в прибор.
- **Не входят в рецепт:** наработка ножей (DT5110/DT5114, см. §f), настройки станка (Form10: ускорения, времена
  хода, пределы высоты, модель), режимы безопасности (H60.04 кожух, H60.05 завеса). Это **настройки станка**:
  отдельная карточка ОБ.099, тоже с версиями.
- **Кто и когда.** Каждая версия хранит автора, время, причину, статус («черновик» → «проба» → «утверждён»), ссылку
  на пробные замеры. Пробные замеры — высота обжима микрометром и отрыв — пишутся как `trial_measurements`.
  Утверждает технолог.
- **Импорт:** 33 строки `craft` → черновики с источником «BZW2.5 craft ID=…». Рецепты 6–13 (китайские коаксиальные
  пины) и 22–42 (TE, Molex, JST, RV) сопоставить с клеммами БД ERP по `ProductModel`. Рецепты с «A» в
  проводе/клемме/аппликаторе требуют разметки.
- **Расхождение рецепта и станка.** Агент постоянно сравнивает параметры в ПЛК с загруженной версией. Наладчик
  поменял высоту на прессе — ERP показывает «параметры изменены у станка: высота 2,500 → 2,520» и предлагает
  сохранить новую версию (черновик) или вернуть. Сегодня в ПЛК высота 2,5 мм, и она не совпадает ни с одним
  рецептом.

## d) Живая панель и команды

**Панель станка** (экран ERP «Оборудование → ОБ.099», раскладка как у ОБ.019):
- **Состояние:** нет связи / «Пожалуйста, сбросьте» (W83.12) / «Сброс выполняется» (W83.13) / «Готов» (W83.14) /
  «Работа» (H60.07) / приработка / CMK / калибровка.
- **Аварии** W80 с русскими текстами из §5 карты и бегущая строка W83.05/.06, W84.13.
- **Задание:** строки D5500–D5540, рецепт и версия, расхождение с рецептом.
- **Счётчики:** план и партия DT5100/DT5102, сделано DT5104/DT5106, годные и брак по CFM.
- **Качество:** высота D5006, последний пик и результат CFM, график последних N пиков.
- **Инструмент:** ресурс и наработка ножа обжима и ножа отсечки, наработка аппликатора по ERP.
- **Входы/выходы:** X0–X11, Y0–Y7 (W66/W68) — для наладчика.

**Команды:**

**Правила безопасности** — те же, что для ОБ.019:
1. **Аварийный стоп — физический**: грибок, кожух, завеса. ERP его не заменяет.
2. «Стоп» доступен всегда, ничем не блокируется и шлётся вне очереди.
3. **Удержание** реализует агент. Кнопка экрана шлёт «держу» каждые 100 мс. Нет сигнала 300 мс → агент снимает
   бит. Пропала связь агента с ПЛК → агент при восстановлении первым делом снимает все удерживаемые биты.
4. Импульсы агент формирует сам (true → пауза 100 мс → false), а не две записи из браузера.
5. Удалённые команды (не с ПК у станка) — только из таблицы выше со «откуда угодно» / «панель ERP».
   Перемещения — никогда.
6. **Аудит:** каждая команда пишется с автором, временем, станком, значениями до и после и результатом
   подтверждения. Журнал только дополняется.
7. Перед первой записью на этапе 2 BZW2.5 закрывается. Агент проверяет, что процесса BZW2.5 нет и порт .50:10001
   свободен.

## e) Качество каждого обжима

**Запись цикла** (таблица `machine_cycle_quality`, только дополняется):
- станок, номер цикла у агента, время;
- задание/операция ЕТК **или** запись ручной работы;
- КБ, если задание его знает;
- оператор — кто вошёл на панели станка (PIN как на складе);
- рецепт и версия, аппликатор (инв. номер), клемма, провод;
- пик (`ActPeak`, единицы — у станка), результат (OK / GrossCDA / сигма), счётчики CFM (Pass, FailGross,
  FailSigma);
- высота D5006 в момент цикла; ссылка на кривую, когда разберём её формат.

**Брак** = FailGross **или** FailSigma. BZW2.5 в журнале считает сигму годной (§6 карты), ERP так делать не будет.

**Сводки:**
- по заданию: годные / брак / выход годных; разброс пика (среднее, σ, Cpk по пробам);
- по оператору и смене;
- по аппликатору: дрейф пика и брака как признак износа.

**Брак останавливает работу.** D5022 «Стоп CFM-NG» остаётся в ПЛК: станок сам встанет после N брака подряд. ERP
показывает аварию W80.03 и просит отметить, что сделано с бракованными клеммами.

**Этапы 0–1:** пока работает BZW2.5, источник — хвост журнала `D:\BZW\logs\yyyyMMdd.txt`. Поля оборудования, изделия,
провода, клеммы и аппликатора там могут быть устаревшими, сигма считается OK. Привязка к заданию идёт по времени и
активному заданию на станке в ERP.

## f) Ресурс аппликаторов и ножей

- **В ПЛК** два счётчика станка: нож обжима (ресурс DT5108, наработка DT5110) и нож отсечки отходов (DT5112 /
  DT5114). BZW2.5 переписывает наработку при загрузке рецепта, то есть фактически ведёт её «на рецепт». ERP так
  делать не будет.
- **ERP ведёт наработку по объектам:**
  - **аппликатор** (`equipment_applicators`): сумма циклов CFM, пока он установлен;
  - **нож/комплект** аппликатора, если они учитываются отдельно;
  - **нож отсечки** станка.

  Каждый цикл добавляет +1 по установленным объектам. Замена аппликатора — явное действие «снять / установить» (со
  сканом), иначе загрузка задания блокируется.
- **В ПЛК оставляем защиту станка как есть:** DT5108/DT5112 = ресурс (из ERP — минимум из остатков установленных
  объектов), DT5110/DT5114 = наработка. При исчерпании ПЛК ставит W83.05/W83.06, станок предупреждает. Сброс W60.13 /
  W60.14 — только с отметкой «нож заменён» (кто, когда, какой нож), что заводит новый счётчик ножа в ERP.
- Пороги: предупреждение при 90 % ресурса, блок новой партии при 100 %. Ресурс по умолчанию — из паспорта
  аппликатора, сейчас в ПЛК 99999.

## g) Переход: сначала чтение, потом рецепты, потом команды

| Этап | Что делаем | BZW2.5 | Запись в станок | Готово, когда |
|---|---|---|---|---|
| 0. Сейчас | Агент на .82: хвост журнала, SELECT `craft`/`alarmrecord`, FINS 01 01 раз в 1–2 с (D5005×80, D5100×45, H60×2, W80×5, строки) | работает | нет | в ERP видны состояние, счётчики, аварии, поштучный OK/NG |
| 1. Рецепты в ERP | Импорт `craft`, библиотека версий, сравнение ПЛК ↔ рецепт; ручная работа и задания как учёт (запуск ещё через BZW2.5) | работает | нет | у каждого задания есть версия рецепта, видны расхождения |
| 2. Запись рецепта у станка | Окно с владельцем у пресса. BZW2.5 закрыта. Агент пишет один рецепт, читает обратно. Владелец открывает BZW2.5 и сверяет экраны Form1/Form7/Form12. Затем пробный обжим, замер высоты. Отдельно проверяем пункты карты §9 | закрывается на время | рецепт + строки + план | 3 рецепта загружены и подтверждены; 20 обжимов с CFM от агента совпадают с ForceView |
| 3. Команды | «Работа/Стоп», сброс, квитирование, счётчики, ресурс ножей; затем ручные перемещения на ПК у станка с удержанием | удалена из автозапуска; остаётся на ПК как запасная | всё из §d | неделя работы без BZW2.5; откат = запустить BZW2.5 |
