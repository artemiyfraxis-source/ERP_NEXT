# API к базе данных («Справочник»)

Программа (Claude Code, скрипт разбора каталогов) читает таблицы «Справочника» и загружает в них строки
(контакты, разъёмы, провода) без браузера и пароля, по токену API.

## 1. Выпустить токен

1. «Доступы» → «Токены API» (только администратор).
2. Название — кто будет ходить с токеном («Claude Code — разъёмы»), срок в днях (1–365).
3. Области:
   - **Чтение базы данных** (`refs:read`) — только чтение таблиц;
   - **Загрузка в базу данных** (`refs:write`) — чтение, правка строк и загрузка.
4. «Выпустить токен» → токен `erp_…` показывается **один раз**: сразу сохраните его (в переменную окружения,
   не в git).

С токеном нельзя заменить базу целиком (снимок «Справочника», загрузка карточек коакса), удалить строку, а также
прочитать или переписать целиком карты «ссылка → поставщик» / «изготовитель → страна» (экран «Соответствия»).
Добавить и поправить строки этих карт токен может через загрузку (раздел 4) — без удаления остальных. Замена
целиком и удаление остаются за человеком в браузере.
Каждая запись по токену попадает в журнал от имени «API: <название токена>». Отозвать токен можно там же,
кнопкой в строке.

## 2. Чтение

```bash
export ERP=https://erp-server.tail811f20.ts.net
export ERP_TOKEN=erp_…            # выданный токен

curl -s -H "Authorization: Bearer $ERP_TOKEN" "$ERP/api/references/bases"
curl -s -H "Authorization: Bearer $ERP_TOKEN" "$ERP/api/references/tech-operations?tab=<база>&q=ZHR&limit=500"
curl -s -H "Authorization: Bearer $ERP_TOKEN" "$ERP/api/references/cables"
```

С токеном не нужен CSRF-заголовок и cookie. Ответ 401 — токен неверный, истёк или отозван; 403 — у токена
нет нужной области.

## 3. Загрузка: сначала проверка, потом запись

Контракт (таблицы, их ключи и поля — в разделе 4):

```
POST /api/references/import/<таблица>?dry_run=1|0&source=api
Authorization: Bearer erp_…
Content-Type: application/json

{"rows": [
  {"fields": {"terArticle": "ZHR-5", "terStep": "1,5"}},
  {"fields": {"terArticle": "PHR-2", "terStep": "2"}, "old": {"terStep": "2,0"}}
]}
```

- `fields` — поля строки. Строка находится в таблице по ключу (у каждой таблицы свои ключевые поля, например
  `terArticle`). Нет такой строки — она создаётся. Есть — меняются только указанные поля; сам ключ не
  переписывается (в базе остаётся его прежнее написание).
- Поле, которого у таблицы нет, отклоняет строку с причиной «неизвестное поле: …». Список полей таблицы:
  `GET /api/references/import/<таблица>/schema` (хватает `refs:read`).
- `null` или отсутствующее поле — **оставить как есть**; `""` — очистить поле.
- **Ничего не удаляется**: строки таблицы, которых нет в загрузке, остаются.
- `old` (необязательно) — значения, которые вы прочитали перед правкой. Если в базе уже другое значение,
  строка отклоняется с причиной «значение изменилось с момента выгрузки» — так загрузка по старой выгрузке не
  затрёт свежую правку человека.
- Значения — текст или число; число записывается текстом (`2.0` → `"2"`).
- Не больше 2000 строк и 8 МБ за вызов, не больше 30 вызовов в минуту на токен (проверки тоже считаются).
- `source` — кто загружает: `api` (по умолчанию), `erp` или `warehouse`; пишется в журнал вместе с именем токена.
- Записанная строка БД.ТЕР / КОАКС / ОБ / ПРОВ / МАТ помечается «правлено в ERP»: перезагрузка зеркала её не
  откатит.

Ответ — отчёт `ImportReport`, одинаковый для проверки и записи:

```json
{
  "dry_run": true,
  "created": ["PHR-2"],
  "updated": [{"key": "ZHR-5", "changes": {"terStep": ["1.5", "1,5"]}}],
  "unchanged": 12,
  "refused": [{"key": "#3", "reason": "не заполнен ключ: terArticle"}]
}
```

- `created` — ключи новых строк; `updated` — ключ и по каждому полю `[было, стало]`; `unchanged` — сколько строк
  уже совпадало; `refused` — отклонённые строки с причиной (`#N` — номер строки в загрузке, если ключа нет).
- Отклонённая строка не мешает остальным: они записываются.
- Составной ключ показан через « / » (`BNC-C58P / RG58`).
- Две строки загрузки с одним ключом (в том числе «ZHR-5» и «ZHR 5» у БД.ТЕР) отклоняются: «ключ повторяется в
  загрузке». Ключ, под которым в таблице несколько строк, отклоняется: такие строки правят в «Базе данных».

Порядок работы:

1. `?dry_run=1`: ничего не записывается, отчёт показывает, что будет.
2. Прочитать отчёт: нет ли лишних `updated`, понятны ли `refused`. Исправить данные, повторить проверку.
3. `?dry_run=0`: запись. Отчёт тот же, что у последней проверки, если базу за это время не меняли.
4. Повторная загрузка тех же строк ничего не меняет (`unchanged` = числу строк) и ничего не пишет в журнал.

Без `dry_run` в адресе вызов работает как проверка: записывает только явный `?dry_run=0`.

```bash
curl -s -X POST -H "Authorization: Bearer $ERP_TOKEN" -H "Content-Type: application/json" \
  --data @ter.json "$ERP/api/references/import/ter?dry_run=1"
```

Коды ошибок всего вызова: 404 — нет такой таблицы; 413 — больше 2000 строк или 8 МБ; 422 — тело не по форме
(`rows` пустой, лишние ключи, неверный `source`); 429 — слишком часто, подождите минуту; 403 — у токена нет
`refs:write` (или у человека нет правки «Справочника»; карты поставщиков и стран человеку открывает ещё право
закупщика).

## 4. Таблицы

| Таблица | Что это | Ключ | Поля `fields` |
|---|---|---|---|
| `ter` | БД.ТЕР — контакты, терминалы и разъёмы | `terArticle` (артикул REEL; ищется как в генераторе: точно, потом без пробелов и `. / ( ) _ -` — и среди артикулов REEL, и среди BAG) | поля схемы (ниже) + колонки листа |
| `coax` | БД.КОАКС — коаксиальные разъёмы | `coaxArticle` + `coaxWire` (артикул + «Провод»; одна строка на пару) | `coaxArticle`, `coaxType`, `coaxMfr`, `coaxWire` + колонки листа |
| `ob` | БД.ОБ — станки и оборудование | `baseValue` («Для базы», как строка видна в базе) | `baseValue`, `obType` + колонки листа |
| `prov` | БД.ПРОВ — кабели и провода | `Марка` (без пробелов и дефисов, без регистра: «UL1061-28AWG» = «UL1061 28AWG») | колонки БД.ПРОВ (ниже) |
| `mat` | БД.МАТ — материалы | `Наименование` (без регистра и лишних пробелов) | колонки БД.МАТ (ниже) |
| `suppliers` | Ссылка → поставщик | `key` (ссылка или домен: `https://www.chipdip.ru/…` = `chipdip.ru`) | `key`, `value` (поставщик) |
| `countries` | Изготовитель → страна | `key` (изготовитель, без регистра и лишних пробелов) | `key`, `value` (страна) |
| `gost_awg` | ГОСТ → AWG | `key` (сечение ГОСТ, мм²: `0,35` = `0.35`) | `key`, `value` (AWG, целое) |
| `wire-gauges` | Сечения AWG ↔ мм² | `awg`, а у строки без AWG — `section_mm2` | `awg`, `section_mm2`, `conductor_d_mm` (скрутки у сечения нет с 0114 — она в строке провода) |
| `hookups` | База монтажных проводов | марка БД.ПРОВ (серия + размер) | файл `hookup-wires.json` целиком (ниже) |

Поля схемы — то, что читает генератор техкарт:

- `ter`: `terManufacturer`, `terSeries`, `terComponent`, `terType`, `terArticle`, `terLPlus`, `terLMinus`,
  `terStep`, `terApplicator`, `terStrip`, `terCrimpHeight`, `terPullForceMin`, `terPullForceMax`, `awgFrom`,
  `awgTo`, `mm2From`, `mm2To`; карточка контакта по протоколу v5.2: `terGender` (Male / Female из «Тип контакта»),
  `terArticleBag` (тот же контакт в упаковке BAG — вторая колонка той же строки, не отдельная строка),
  `terInsCrimpHeight`, `terInsOdFrom`, `terInsOdTo`, `terMaterial` («Металл / Покрытие»), `terMaxCurrent` (А),
  `terDatasheet` (ссылка на сайт производителя);
- `coax`: `coaxArticle`, `coaxType`, `coaxMfr`, `coaxWire`; колонки карточки разъёма принимаются и до того, как они
  есть у строк: «Тип пина», «Тип экрана», «Серия», «Пол», «Полярность», «Исполнение», «Монтаж», «Центральный
  контакт», «Крепление экрана», «Волновое сопротивление, Ом», «Частота до, ГГц», «Материал корпуса», «Покрытие»,
  «Габариты», «Наименование», «Ссылка», «Примечание», «Источник данных»;
- `ob`: `baseValue`, `obType`.

Колонки листа («Шаг разьема», «Артикул контакта (REEL)», «Инв. номер»…) — как их показывает «База данных»; точный
список в базе отдаёт `…/import/<таблица>/schema` (`schema_fields`, `sheet_columns`). Значение поля схемы пишется и в
колонку, из которой оно читается (`terStep` → «Шаг разьема»), а колонка — в своё поле схемы, так что генератор и
экран видят одно. Поле схемы и его колонка в одной строке с разными значениями отклоняют строку. `connType`,
`artISL`, `artSAG`, `supplier`, `program` генератор не хранит — их пишут через колонки листа.

`ter` по протоколу контактов v5.2: аппликатор (`terApplicator`, «Аппликатор»), «Пневма Автомат», «ОТР», «С
зачисткой» и мм² (`mm2From`, `mm2To`, «От мм2», «До мм2») заполняет технолог — строка с любым из них отклоняется,
мм² из AWG не считаются. Усилие обрыва хранится в Н: значения в kgf/кгс умножаются на 9,8, в lbf — на 4,448
(округление до 0,1); AWG пишется без «#»; материал — «Металл / Покрытие». Значения обжима, которых нет в документации
производителя, не присылайте: пустое не усредняется и не подставляется. `terGender`, расходящийся с присланным в той
же строке «Тип контакта», отклоняет строку; присланный без него становится типом контакта. База (миграция 0115) держит
карточку проверками: `terGender` — Male, Female или пусто (непонятное слово отклоняет строку); `terInsOdFrom` /
`terInsOdTo` — пусто или число мм больше нуля, «от» ≤ «до» (с учётом уже записанного); `terDatasheet` — пусто или
ссылка http(s)://. Такая строка отклоняется с причиной, остальные пишутся. `GET /api/references/tech-operations?tab=ter`
отдаёт у каждой записи `card` — карточку контакта для экрана «Терминалы». Тело загрузки из зеркала
БД.ТЕР (по артикулу REEL: производитель, серия, тип и карточка контакта):
`python -m app.modules.references.load_mirror --export-ter ter.json`.

Колонки `prov`: «Марка», «Тип провода», «Стандарт / производитель», «Сечение, мм2», «AWG», «Жила: проволок ×
диаметр, мм», «Число жил», «Цвета», «Наружный диаметр, мм», «Изоляция», «Экран», «Волновое сопротивление, Ом»,
«Темп. от, °C», «Темп. до, °C», «Напряжение, В», «Ток, А», «Масса, г/м», «Закупок», «Цена посл., ₽/м без НДС»,
«Поставщик», «Ссылка на datasheet», «Источник данных». У разобранного монтажного провода правка сечения, AWG,
диаметра, изоляции, напряжения и температур двигает и его структуру — как правка в «Базе данных».

Колонки `mat`: «Наименование», «Группа», «Производитель», «Серия», «Размер до, мм», «Размер после, мм», «Коэф.
усадки», «Цвет», «Клеевой слой», «Материал», «Темп. от, °C», «Темп. до, °C», «Ед. изм.», «Закупок», «Цена посл., ₽
без НДС», «Поставщик», «Ссылка на datasheet», «Источник данных».

Карты (`suppliers`, `countries`, `gost_awg`) — только добавить или поменять значение, ничего не удаляется.
«Изготовитель → страна» сравнивается с тем, что показывает экран (сохранённое + встроенный список); пока «ссылка →
поставщик» ни разу не сохраняли, первая загрузка сохраняет и встроенный список, который был на экране. ГОСТ → AWG
следует «Сечениям AWG ↔ мм²»: сечение, которое там есть с другим AWG, отклоняется — меняйте его в таблице сечений.

`wire-gauges`: числа — `0,5` или `0.5`, отчёт показывает их с запятой; ключ в отчёте — «20 AWG» или «0,07 мм²».
Запись сечения обновляет и ГОСТ → AWG.

```bash
  --data "$2" "$ERP/api/references/import/$1?dry_run=1"; }

post ter '{"rows":[{"fields":{"terArticle":"ZHR-5","terManufacturer":"JST","terStep":"1,5","terGender":"Female","awgFrom":"28","awgTo":"26"}}]}'

post prov '{"rows":[{"fields":{"Марка":"UL1061 28AWG","Цвета":"чёрный, красный","Наружный диаметр, мм":"0,89"}}]}'

  --data @backend/data/cables/hookup-wires.json "$ERP/api/references/import/hookups?dry_run=1"

# Коаксиальные разъёмы gsm-repiteri.ru (311 разъёмов → строки «разъём × кабель» БД.КОАКС): тело собрано
# `python -m app.modules.references.coax_connectors` из backend/data/cables/coax-connectors-gsm.json
curl -s -X POST -H "Authorization: Bearer $ERP_TOKEN" -H "Content-Type: application/json" \
  --data @backend/data/cables/coax-connectors-gsm.import.json "$ERP/api/references/import/coax?dry_run=1"

# Поля таблицы

```

Запись — тот же вызов с `?dry_run=0`. Отчёт `hookups` — тот же `ImportReport` плюс свои разделы
(`gauges_added`, `gauge_mismatches`, `moved_out_of_montage`, `counts`); формат файла описан в
`backend/app/modules/references/importers.py`.

## Для разработчика

Таблицы — `backend/app/modules/references/importers.py` (`import_rows`, `import_schema`, `import_hookups`),
адреса — `references/import_api.py`. Рамка — `backend/app/shared/bulk_import.py`: `ImportRequest` / `ImportReport`, `ImportTable` (ключевые поля,
допустимые поля, событие журнала), `ImportTarget` (чтение строк по ключу, создание, правка, журнал,
commit/rollback над единицей работы модуля) и `run_import(...)`. Обработчик таблицы ставит ворота
`references_edit_principal` (токен с `refs:write`) и отвечает `HTTPException(error.status_code, str(error))` на
`ImportRefused`. По умолчанию `dry_run=1`. Ограничение частоты считается внутри одного процесса API.
